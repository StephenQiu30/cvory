# 在线简历制作设计

2026 年 11 月 24 日 · 首版实施设计。产品范围来自[极简简历制作需求](../requirement/01-极简简历制作需求.md)，十二条需求、原话及逐项答复见[需求导航](../requirement/00-需求导航.md)。

## 1. 摘要

用户在首页用同一份虚构履历比较三款纸样，选用后进入空稿，填写并核对自己的简历，再取得免费、无水印、中文可复制的 A4 PDF。游客可先完成整条流程，需要换设备时再用邮箱验证码登录。「我的简历」负责按岗位管理多份稿件。

## 2. 参与者

选模板者重视纸样好看、清楚、可直接使用。撰写者重视填好的内容能找回、修改和投递，两者可以是同一人。产品与设计确认操作规则、Figma 和纸样，前端负责编辑和 PDF，后端负责身份与同步，测试负责用真实浏览器、设备和 PDF 阅读器复核。

## 3. 背景

简序已有模板库、本机草稿列表及响应式编辑器，账号续写仍需联调。竞品桌面可同屏展示纸样和使用入口，窄屏实测会把部分纸张与操作挤到首屏之外。简序把「使用模板」放在纸样旁，编辑器用独立的填写与预览视图适配手机。当前 Figma 设计覆盖模板入口、桌面与手机编辑、岗位稿管理、邮箱认领、同步反馈、排版与导出状态。[市场与输入体验调研](../research/05-简历制作市场调研与输入体验设计.md) · [老鱼简历路径与开源方案依据](../research/08-开源简历项目与首版业务闭环.md) · [Figma 首版设计总览](https://www.figma.com/design/aPto1XhOXlYWZHQVWnHaL9?node-id=16-1474) · [桌面编辑器](https://www.figma.com/design/aPto1XhOXlYWZHQVWnHaL9?node-id=17-1444)

## 5. 使用场景

- **先挑模板。** 打开放大纸样，看同一份经历在不同模板下的文字密度和留白，然后使用其中一款。
- **从经历起笔。** 粘贴一段项目成果，在预览发现第二条有误，点纸面定位到原字段修改。
- **跨设备准备多个岗位。** 手机上写第一稿，登录认领后在电脑上复制为另一个岗位版本。设备短时断网仍能改动本机已有稿件并导出。

## 6. 价值

用户写一次正文即可比较版式、继续修改或复制给另一岗位。在选择模板时就能看到实际排版，导出时拿到刚在预览里核对过的那份文件。

### 首版完整路径

| 起点 | 正常路径 | 异常与恢复 |
| --- | --- | --- |
| 游客第一次制作 | 在模板库比较三款纸样并选用。在空稿中完成手动填写，通过纸面定位、调整版式并下载 PDF。返回「我的简历」后可打开本机稿继续编辑 | 空稿或倒序日期定位到可修改位置。字库加载失败或生成中断时保留正文，可就地重试。生成期间改稿或切稿时，旧结果停止交付 |

### 无边框编辑器与组件

桌面显示章节导航、填写、纸面三栏。实施从 1200px 三栏起测，左栏宽 184px，填写区和预览区各留约 420px 的可用宽度。窄屏显示「填写／预览」标签，标题、保存状态和下载按钮仍可找到。填写与预览分别记住本稿滚动位置。点击纸面某段时，用稳定条目 ID 定位，手机先切到填写再滚动和聚焦。章节排序支持可用键盘操作的上移、下移。

桌面章节标题 17px、输入 14px、操作 13px。手机输入至少 16px，主要触控区按 44px 起测。界面采用近白画布、浅底字段、白纸、深色主操作与蓝色键盘焦点。按 4px 网格组织留白，控件圆角 6px、纸面直角。错误文字关联到字段，长邮箱和岗位名有换行或完整查看方式。[无边框需求与样式参考](../requirement/06-无边框视觉与组件.md)

界面色板采用 Vercel Geist 浅色版的 sRGB 色值。以下语义变量由 Figma 和前端共用。简历纸面的主题色仍按所选模板及用户设置计算。

| 页面画布 | `--canvas` | `#FAFAFA` |

### 输入、显隐与排序

| 章节 | 首版字段 | 编辑和成品规则 |
| --- | --- | --- |
| 基本信息 | 姓名、意向岗位、电话、邮箱、所在地，可选联系方式与个人链接 | 各字段可独立填写。可选字段从预设字段中按需显示或移出，恢复使用原值。空值不占位置 |
| 教育 | 学校、专业或学位、起止月份、补充说明 | 可增删多段，同名学校依条目 ID 辨别 |
| 工作、项目 | 公司或项目名、岗位或角色、起止月份、多行经历 | 可添加、移动或删除条目。粘贴保留原有换行。删除有内容的条目前确认 |
| 技能 | 多行文字 | 保持输入顺序，空段落不产生章节标题 |

初始章节顺序为基本信息、教育、工作、项目、技能。五章均可移动或隐藏。隐藏章和移出的可选字段都可恢复原值。允许只填一项。以可见且有效的内容判断是否为空稿，纯空格、示例和文件名均不计入。日期按月填写，可留空一端，选择「至今」时清空结束月。可见条目的结束月早于开始月时，保存输入并标出错误，下载时定位到第一个错误。隐藏条目不参与此次 PDF 校验。该校验口径供原型核对。

### 模板与个人排版

纸样使用同一份虚构履历，模板的段落与字段结构相同。三款均按 A4 分页，章节标题与首行同页，必要时一段经历可跨页续排。

| 模板 | 默认视觉 | 使用场景 |
| --- | --- | --- |
| 经典单栏 | 左对齐姓名，靠字重区分章节，标准留白 | 通用履历 |
| 紧凑单栏 | 日期靠右，短分隔线，收紧条目间距 | 工作或项目条目多 |
| 中文书简 | 黑体标题、宋体正文，宽松留白 | 重视连续中文阅读 |

「排版」面板按当前稿显示字体、字号、行距、间距、主题色与「恢复模板默认」。试样范围采用黑体／宋体、正文 9–12pt、行高 1.25–1.65、紧凑／标准／宽松三档和少量预设主题色。具体档位、色值和可嵌入的字库以 T-CV-01 样张及 T-CV-02 实测定稿。纸面方案与界面字号分开。

模板切换只更新模板 ID。有效样式按字段取个人覆盖值，未设置的项取该模板默认值。恢复默认在同一次操作中清除五类个人覆盖值。并发修改按字段合并，同稿各端计算出相同的有效样式。预览、下载和第二台设备从同一份稿计算有效值，公共模板的默认值独立管理。[个人排版决定](../requirement/12-个人简历排版设置.md)

### 现行数据、认领与同步

| 对象 | 实施契约 |
| --- | --- |
| 文档身份 | 每稿独立、不可复用的文档 ID。账号记录保存所有权、稿名、更新时间和删除状态。浏览器用文档 ID 和身份分隔工作区数据。退出登录或切换账号时关闭旧连接与稿件视图，清除内存预览；未同步改动保留在原账号本机空间，原账号恢复后接着同步 |
| 正文与顺序 | 一个文档对应一个 Y.Doc。可并发输入的纯文本按字段使用 Y.Text，工作经历、项目经历和技能正文使用 Tiptap 绑定的 Y.XmlFragment，使两端对同一段的独立输入都能合并。章节、条目、可选字段及个人版式按稳定键保存。条目内容存在独立于顺序的稳定记录。以各端都能复现的规则解析顺序，每个有效 ID 只出现一次。删除的经历始终从成品排除，另一端稍后提交对该经历内容或顺序的更新也不能恢复它 |
| 快照 | 下载只读取当前稿的有效内容与样式。复制读取当前已提交到编辑模型的快照，以新 ID 建立独立文档，后续更新分别同步 |
| 账号与认领 | 邮箱验证码过期、限频且只能使用一次。验证成功后建立会话。认领针对当前用户明确选定的单份本机稿。用账号与本机稿 ID 标识同一次认领，首次写入与绑定一次完成。回执丢失时重试返回同一目标稿。保持该稿的 Yjs 历史，认领期间继续写入同一份本机稿，持久保留绑定和待发送更新。请求超时或页面重开后，在原账号下向同一目标稿重试或续传。收到目标稿覆盖本机修改的持久化回执后，把该稿从游客列表移到账号列表 |
| 同步写入 | 重连交换文档差异。服务端在读写时以当前会话校验所有权、当前契约和稿件存活状态。存储提交后返回能识别本批更新的回执；客户端只在收到覆盖当前文档最新本机变更的回执时显示「已同步」。更新重试须保持同一结果 |
| 删除与无效输入 | 稿件删除与更新按服务端已提交状态判定。删除成功后，已连接或重连设备都停止同步该稿并更新本机列表。收到删除状态前在离线设备上做的编辑仍可在该设备导出，设备重连发现删除时提示用户并让当前账号先下载本机版本，用户确认移除后清理这份本机副本。非所有者与不支持的契约拒绝读写，现行稿保持可用 |

| 状态 | 用户看到的反馈与操作 |
| --- | --- |
| 游客本机写入成功 | 「已保存到此设备」，可以主动开启跨设备保存 |
| 账号稿本机已保存，远端尚无最新回执 | 在线显示「同步中」，断网后显示「待同步」。本机已有稿可继续写与导出 |
| 远端确认最新更新持久化 | 「已同步」。只覆盖较早修改或属于其他稿件的回执跳过状态更新 |
| 本机写入失败 | 「本机保存失败」及重试。只要当前稿仍在内存就可编辑和导出 |
| 会话需要续期或同步失败 | 提示重新验证或重试，保留已经写入本机的内容 |

网络中断前已打开的稿必须可以继续操作。离线重开从已准备好的设备和稿件进入。稿件写入本机且应用、当前纸样和所需字体缓存成功后，才提示该稿可离线续写并导出。首次在设备 B 打开尚未下载的账号稿需要联网。离线时只恢复本机仍处于登录状态的身份。退出登录后须重新验证，才可再次打开该账号的缓存。切换模板或字体需要尚未缓存的字库时，保留可用版本并提示联网加载。本机缓存与身份管理、持久化回执采用现行契约，旧格式校验失败即停止本次读写。[跨设备续写](../requirement/09-跨设备续写.md) · [单一现行数据契约](../requirement/13-单一现行数据契约.md)

### 预览与 PDF 管线

正文、模板和有效样式组成带文档 ID 与生成序号的快照。对输入停顿、切到预览或发起下载生成 PDF。预览用 PDF.js 展示这一产物，下载使用同一份字节。导出绑定发起时的稿件、生成序号和文件名；等待期间若当前稿件、名字、正文或排版发生变化，取消旧请求，提示对当前版本重新下载。输入法组合期间等待选词完成再发起。用纸面锚点关联稳定条目 ID，实现可随缩放和多页滚动定位的表单入口。生成失败时提供重试，保留正文。文件名清理无效字符。

Next.js、shadcn/ui Radix、Tailwind CSS、Axios + `@umijs/openapi`、Tiptap、Yjs + `y-indexeddb` 与 NestJS + PostgreSQL + Prisma + Redis + 无状态 JWT + 网易 163 邮箱 SMTP 为首版实现基线。PDF 生成引擎在 T-CV-02 优先验证 **Typst WASM（`@myriaddreamin/typst.ts`）**，核验自托管完整开源 OFL 中文字库（思源黑体／思源宋体）、Tiptap 富文本映射、中文断行、分页、`query` 条目坐标定位与离线生成；若真机实测存在不可解 WASM 阻断则降级至 `pdf-lib + @pdf-lib/fontkit`。候选须保留完整中文文本和原标点，下载不得依赖联网或打印对话框。材料只用虚构数据，日志与测量记录去掉正文、邮箱和电话。[技术选型与系统架构设计](02-技术选型与系统架构设计.md) · [开源选型和实测](../research/07-开源编辑同步与PDF排版选型.md)
