# 在线简历制作执行计划

唯一来源 PRD 为[在线简历制作 PRD](../prd/01-在线简历制作PRD.md)，工程架构与选型基线见[技术选型与系统架构设计](../design/02-技术选型与系统架构设计.md)。首版按已确认范围验收。内部里程碑用于安排依赖和并行，任务进度在[项目 BACKLOG](https://github.com/StephenQiu30/cvory/blob/main/BACKLOG.md)记录。

## 开工顺序

| 阶段 | 先做什么 | 阶段完成条件 |
| --- | --- | --- |
| M1 · 设计与技术定型 | T-CV-01 先锁样例和页面状态。T-CV-02 用同一组数据验证浏览器生成路线。样例固定后可同时启动模板入口、编辑器骨架和身份接口准备 | 页面状态和样例可复现。PDF 原型通过中文连续长段、离线下载和纸面定位验证，留下版本与文件 |
| M2 · 本机制作闭环 | T-CV-03、T-CV-04 实现模板及填写。PDF 试验通过后，T-CV-05 集成预览及下载，T-CV-09 验证本机个人排版。T-CV-07 可在编辑契约确定后并行 | 游客可在桌面和手机从纸样走到可投递 PDF。本机保存、刷新与断网可验证 |
| M3 · 账号与发布 | T-CV-08 接账号稿件管理。T-CV-06 联验 T-CV-07、T-CV-08 和本机制作的合并版本 | 同一邮箱双设备、岗位管理、个性排版与现行契约均验收。证据齐全后评审发布 |

优先承接 T-CV-01，并为 T-CV-02 接上一个可独立运行的原型。工程承接后登记实际负责人和预估工期。中文 PDF 原型与测试邮箱的实际结果用于估算集成和联验。

## 实施位置和职责

| 实施位置 | 责任 |
| --- | --- |
| `frontend/` 的页面层、组件与接口 | 基于 Next.js + shadcn/ui Radix + Tailwind CSS + Axios + `@umijs/openapi`，负责首页、编辑页、「我的简历」、邮箱入口、JWT 续期拦截与 Service Worker 离线重开 |
| `frontend/` 的简历模型与编辑 | 定义稳定 ID、字段、顺序、显隐、个人排版、Tiptap 富文本（MIT 扩展）与 Yjs / `y-indexeddb` 绑定和账号命名空间隔离 |
| `frontend/` 的纸样与 PDF 管线 | 负责三款纸样预设、快照投影、Typst WASM（`@myriaddreamin/typst.ts`，兜底 `pdf-lib`）离线编译、Tiptap 到 PDF 映射、PDF.js 预览、`query` 页坐标与自托管开源 OFL 中文字库按需缓存 |
| `backend/` 身份与同步模块 | 基于 NestJS + `@nestjs/swagger` + Prisma + PostgreSQL + Redis，负责网易 163 邮箱 SMTP 验证码（开发走 Mailpit）、无状态 JWT + Redis 黑名单与限频、文档所有权、单稿幂等认领、原生 `ws` Yjs 同步、现行契约校验、远端持久化与显式 `ACK` 回执 |
| 基础设施与容器编排 | 根 `docker-compose.yml` 仅编排 `frontend`、`backend` 与独立 `workspace` 业务容器，PostgreSQL 与 Redis 直接复用宿主机已有服务 |
| 产品测试与样例 | 负责虚构履历、页面流程、PDF 文件验收和双设备实验，全程记录构建版本 |

## 验证与发布

每条验收记录包含场景号、构建版本、虚构样例、设备与浏览器、操作、预期和实际结果。浏览器测试覆盖首访、本机刷新、点击定位、乱序结果和切稿。真实手机复核输入法、窄屏、离线打开及系统阅读器复制。PDF 用阅读器及文本提取工具核对 A4、总页数、标点和跨页文字。同步记录本机、远端持久化和另一设备读回的时间点，只保留非敏感状态。

联验使用同一候选版本、两台设备和两个测试身份。验证关闭网络、服务重启、认领重试、删除后重连和拒绝不受支持的契约。小样本用户试用记录独立完成和选款成功数、耗时、分母及卡点。产品签收以 PRD 中的发布门槛和每条结果为准。

发布前记录候选版本、测试入口和回退操作人。出现丢稿、串稿、错误导出或越权，暂停公开入口或撤下候选，保留草稿与远端存储。修复后使用现行契约复跑续写、双设备和导出，再恢复发布。首版应用只交付现行契约，验收重点是拒绝不支持的输入时仍能继续使用已保存的当前稿件。
