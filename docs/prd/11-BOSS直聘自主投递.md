# BOSS 直聘自主投递

唯一来源 design：[设计 02](../design/02-CV制作管理与展示设计.md)。PRD-CV-11。自主实现、允许基于开源改造为已确认方向；以下定义具体目标验收，首期只支持 Chrome，PDF 由用户在平台手工上传，插件仅筛选/沟通/招呼；MV3 侧栏和开源复用为建议，分发方式待选。实施和验证状态见 BACKLOG。

## 1. 用户结果与范围

作为求职用户，我可以从 CVory 选择简历、PDF 和岗位，核对将发送的内容后，在自己登录的 BOSS 账户中执行，并知道沟通/招呼的实际结果与人工材料准备状态。

完整目标的首期闭环为 Chrome 插件、人工 PDF 准备、关键词/排除词/城市/薪资等规则配置、可选 AI 匹配、有限岗位选择、固定简历快照、明确启动、分动作执行、暂停／停止、异常交回及结果核验。岗位可来自支持的读取方式或链接录入，不以建设完整职位搜索引擎为前提。仅准备材料不向外发送。手机可准备／管理，实际执行遵守选定执行器的设备边界。

**当前授权边界**：负责人确认暂无或不确定具备覆盖插件读取岗位和发送招呼的 BOSS 书面授权；官方可查协议版本的条款也未能确认为当前生效版本。因此当前实现范围限于 CVory 内手工录入/粘贴岗位、关键词/城市/薪资筛选、招呼草稿、固定简历及人工 PDF 准备和离线模拟。当前构建不得申请 `zhipin.com` 主机权限，不得读取平台页面、Cookie 或接口，不得发送消息；模拟结果必须与真实平台结果有明确区分。该阶段不代表原始需求的真实插件闭环已经完成。

不包括其他招聘平台、无人值守海投、验证码绕过、代管平台密码、自动回复协商、录用承诺或招聘方管理。云端故障及平台不可用不影响私有简历制作和备份。

## 2. 完整流程

1. 连接用户控制的本地执行环境，在平台官方页面登录；查看当前 CVory 账户、设备及 BOSS 账户，明确连接状态。
2. 由浏览器插件读取或录入岗位，按关键词等硬条件筛选，再可选 AI 对照；核对职位/公司/未知条件，选择有限岗位集合；失效、不支持或信息过期的岗位不能伪装可投。
3. 选择已保存 CV，固定 etag/内容；需用 PDF 时下载固定文件并由用户在 BOSS 官方页面手工上传。可记录用户确认及文件标识，但不推断平台文件内容一致或送达。
4. 显示目标岗位、平台账户、简历及发送内容，用户明确启动；重复点击启动不新建相同执行。
5. 逐项展示沟通/招呼处理中、确认、失败、未知或跳过；人工 PDF 准备单独显示待处理或用户确认，不算平台送达。
6. 可暂停后续动作或停止；登录／平台限制交回用户处理，恢复前核对未知动作。任务结束显示各状态数量，不把“结束”当作全部成功。

## 3. 验收条件

- **AC-BOSS-01 自有入口**：在 CVory 中完成准备和结果管理，平台差异封装在自有适配器；不要求用户自行拼接外部 CLI 命令。未选执行方案时不展示虚假可用发送入口。
- **AC-BOSS-02 连接与身份**：用户端官方登录，绑定当前 owner、设备及平台账户；不上传账号密码或 Cookie。离线、绑定撤销及账号切换有明确状态，不继续原授权发送。
- **AC-BOSS-03 岗位与范围**：显示岗位来源、公司及读取时间，支持逐项选择、移除和核对；失效／重复／不支持链接准确提示。没有用户选择的岗位不加入发送集合。
- **AC-BOSS-04 固定材料**：所选 CV、etag、内容和招呼输入固定；选择 PDF 时固定版本/文件摘要供人工核对，用户自行上传。首期不创建自动附件动作；新编辑、模板变化和历史恢复不追改任务，也不替换平台已有文件。
- **AC-BOSS-05 明确启动**：启动前可核对岗位、平台身份、固定简历、招呼及动作范围；人工上传 PDF 如有记录只作为用户说明；取消不发送，未授权任务不能被其他操作启动。
- **AC-BOSS-06 分动作结果**：授权后的真实平台版本分别核实建立沟通和招呼文字；人工上传状态注明用户报告来源。首期不上传/发送 PDF 或 PNG，不创建“附件发送成功”状态；无回执显示未知，不暗示附件送达、已读、回复或录用。当前阶段仅允许 simulation 状态，不能展示真实成功文案。
- **AC-BOSS-07 暂停与停止**：暂停／停止阻止后续领取和发送，已发材料不承诺撤回；在途动作允许先核实后更新结果，不展示虚假的全部取消。
- **AC-BOSS-08 重试与去重**：重复提交、断网、回执丢失、租约失效、服务或执行器重启不能自动重复已确认或未知动作；先核对平台状态，再由用户决定后续。一次任务项同一动作只有一个有效执行者。
- **AC-BOSS-09 平台异常**：登录失效、验证码、限制、岗位关闭、需要人工处理材料等分别提供可理解原因及下一步；不绕过验证或持续重试发送。
- **AC-BOSS-10 隔离与撤销**：另一账户不能列举、修改、领取任务或获取 PDF／证据；设备撤销及账户注销后不能领取新动作，隐私清理遵循设计，日志无凭据或完整简历。
- **AC-BOSS-11 结果可追溯**：任务展示固定材料标识、岗位、动作类型、时间和受限结果证据，未知与失败不混合为成功；证据丢失／过期要说明，不能据此补造平台回执。
- **AC-BOSS-12 故障降级**：平台／执行器／任务服务故障不阻止 CV 保存、JSON／Markdown 下载和已有 PDF 的人工使用；界面说明设备要求，不伪称后台持续运行。

- **AC-BOSS-13 规则与匹配**：展示关键词、排除、城市/薪资等规则及每项命中/不符/未知；必需条件未知进入待核对，AI 不能偷偷放宽条件。修改偏好不追改已启动任务；无 AI 时硬条件筛选和手工准备仍可用。
- **AC-BOSS-14 插件边界**：当前构建不声明 BOSS host permission/content script，不访问 BOSS 页面、Cookie 或接口；仅以用户手工提供或合成岗位验证规则与任务 UI。若未来通过授权门槛，再由用户 Chrome 连接当前 owner 和平台账号；关闭/worker 回收后准确显示中断、重连核查，不承诺无浏览器后台执行，页面消息不能伪造领取或授权，插件仅申请必要域名权限。
- **AC-BOSS-15 跨任务去重**：同平台账号和岗位/HR 的历史动作可检索，不因另建任务、换 CV 或 worker 重启自动重复；unknown 必须先核查。人工 PDF 上传确认与自动沟通/招呼结果分开；不得发送 PNG 替代，也不因用户确认就断言平台已收到对应 PDF。
- **AC-BOSS-16 平台授权门槛**：没有现行官方规则核验及适用书面授权时，任何运行时配置都不能打开真实 BOSS 页面访问或发送能力；当前构建没有相关 host permission、content script、Cookie/API 访问或真实动作实现。模拟服务接受的结果只标记为模拟，不落成真实投递记录。授权材料和现行协议复核完成后，须单独评审与交付真实适配。
- **AC-BOSS-17 离线任务快照**：创建离线任务时固定当前 owner、CV 内容及 etag、偏好、岗位字段、筛选依据和招呼草稿；相同 requestId 不重复建任务，复用 requestId 但请求内容不同则拒绝。之后改动简历、偏好或岗位不改写快照；模拟后只标记“已模拟”。任务列表和详情按 owner 隔离，用户可删除任务。

## 4. 验证场景

| 场景 | 动作及可观察结果 | 对应 AC |
| --- | --- | --- |
| TC-BOSS-01 准备与取消 | 两个合成岗位、固定 CV／PDF，编辑内容后核对任务；取消 → 不发送，快照不变化 | 01、03～05 |
| TC-BOSS-02 身份切换 | 两个 owner、设备离线、切换平台账号、撤销连接 → 拒绝越权及旧身份授权，提示重连 | 02、10 |
| TC-BOSS-03 分动作核验 | 模拟沟通成功/文字未知与人工 PDF 未报告/用户已确认 → 来源及状态分别准确，无自动附件动作 | 06、11 |
| TC-BOSS-04 未知与并发 | 发送后丢回执、双执行器、延迟确认、重启重连 → unknown 不自动重放，无双重领取 | 07、08 |
| TC-BOSS-05 平台条件 | 模拟失效登录、验证码、限制、岗位关闭及附件要求 → 停止相关发送，明确人工处理 | 09 |
| TC-BOSS-06 清理与降级 | 账户注销、连接撤销、平台不可用 → 不能领取，材料受控；私有保存和备份仍可用 | 10、12 |
| TC-BOSS-07 真实平台闭环 | 仅在现行协议核验和平台授权门槛满足后，由用户明确指定账号、岗位及范围逐动作核对；当前未授权，保持阻止并记为未验收 | 02～11、16 |
| TC-BOSS-08 离线规则与模拟 | 使用手工录入岗位执行关键词、城市、薪资和排除条件；创建任务后改动原资料，原快照不变；相同请求幂等，模拟结果只标记“已模拟”，可删除；构建不申请 BOSS 域名权限且不产生到 BOSS 的网络、页面或消息动作 | 01、03～06、10、12～14、16～17 |

补充规则样本与未知薪资/JD、AI 故障、跨任务重复、资产被修改、插件 worker 回收与伪造页面消息场景；验证首期不产生附件上传/发送请求，人工确认不冒充平台回执（AC-BOSS-13～15）。

模拟适配器只证明内部状态与故障处理。真实平台闭环须单独验证；没有授权岗位时停留在准备、模拟与只读核查，不发送测试消息。任何平台行为变化均需重新确认适配行为，不能从开源 README 的“apply”推断附件投递成功。
