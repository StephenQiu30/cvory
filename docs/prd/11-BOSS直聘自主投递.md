# BOSS 直聘自主投递

唯一来源 design：[设计 02](../design/02-CV制作管理与展示设计.md)。PRD-CV-11。自主实现、允许基于开源改造为已确认方向；以下定义具体目标验收，执行形态与上游基座按设计选定。实施和验证状态见 BACKLOG。

## 1. 用户结果与范围

作为求职用户，我可以从 CVory 选择简历、PDF 和岗位，核对将发送的内容后，在自己登录的 BOSS 账户中执行，并知道沟通、招呼及附件分别完成到哪一步。

首期闭环为有限岗位选择、固定简历快照、明确启动、分动作执行、暂停／停止、异常交回及结果核验。岗位可来自支持的读取方式或链接录入，不以建设完整职位搜索引擎为前提。仅准备材料不向外发送。手机可准备／管理，实际执行遵守选定执行器的设备边界。

不包括其他招聘平台、无人值守海投、验证码绕过、代管平台密码、自动回复协商、录用承诺或招聘方管理。云端故障及平台不可用不影响私有简历制作和备份。

## 2. 完整流程

1. 连接用户控制的本地执行环境，在平台官方页面登录；查看当前 CVory 账户、设备及 BOSS 账户，明确连接状态。
2. 查看或录入岗位链接，核对职位／公司，选择有限岗位集合；失效、不支持或信息过期的岗位不能伪装可投。
3. 选择已保存 CV，固定 etag、内容、有效样式和真实 PDF；可核对文件、招呼文本及动作范围。
4. 显示目标岗位、平台账户、简历及发送内容，用户明确启动；重复点击启动不新建相同执行。
5. 逐项展示处理中、确认、待处理、失败、未知或跳过；按平台条件区分沟通、文字和附件。
6. 可暂停后续动作或停止；登录／平台限制交回用户处理，恢复前核对未知动作。任务结束显示各状态数量，不把“结束”当作全部成功。

## 3. 验收条件

- **AC-BOSS-01 自有入口**：在 CVory 中完成准备和结果管理，平台差异封装在自有适配器；不要求用户自行拼接外部 CLI 命令。未选执行方案时不展示虚假可用发送入口。
- **AC-BOSS-02 连接与身份**：用户端官方登录，绑定当前 owner、设备及平台账户；不上传账号密码或 Cookie。离线、绑定撤销及账号切换有明确状态，不继续原授权发送。
- **AC-BOSS-03 岗位与范围**：显示岗位来源、公司及读取时间，支持逐项选择、移除和核对；失效／重复／不支持链接准确提示。没有用户选择的岗位不加入发送集合。
- **AC-BOSS-04 固定材料**：所选 CV、etag、内容、样式和 PDF 内容摘要固定；保存失败或 PDF 未验证不得启动附件发送。新编辑、模板变化和历史恢复不追改任务。
- **AC-BOSS-05 明确启动**：启动前可核对岗位、平台身份、招呼、附件和动作范围；取消不发送，未授权任务不能被其他操作启动。
- **AC-BOSS-06 分动作结果**：建立沟通、招呼文本、附件分别核实；招呼成功但附件失败／待对方同意时不能标记附件成功。无回执显示未知，不暗示已读、回复或录用。
- **AC-BOSS-07 暂停与停止**：暂停／停止阻止后续领取和发送，已发材料不承诺撤回；在途动作允许先核实后更新结果，不展示虚假的全部取消。
- **AC-BOSS-08 重试与去重**：重复提交、断网、回执丢失、租约失效、服务或执行器重启不能自动重复已确认或未知动作；先核对平台状态，再由用户决定后续。一次任务项同一动作只有一个有效执行者。
- **AC-BOSS-09 平台异常**：登录失效、验证码、限制、岗位关闭、附件不兼容及需要对方许可分别提供可理解原因及下一步；不绕过验证或持续重试发送。
- **AC-BOSS-10 隔离与撤销**：另一账户不能列举、修改、领取任务或获取 PDF／证据；设备撤销及账户注销后不能领取新动作，隐私清理遵循设计，日志无凭据或完整简历。
- **AC-BOSS-11 结果可追溯**：任务展示固定材料标识、岗位、动作类型、时间和受限结果证据，未知与失败不混合为成功；证据丢失／过期要说明，不能据此补造平台回执。
- **AC-BOSS-12 故障降级**：平台／执行器／任务服务故障不阻止 CV 保存、JSON／Markdown 下载和已有 PDF 的人工使用；界面说明设备要求，不伪称后台持续运行。

## 4. 验证场景

| 场景 | 动作及可观察结果 | 对应 AC |
| --- | --- | --- |
| TC-BOSS-01 准备与取消 | 两个合成岗位、固定 CV／PDF，编辑内容后核对任务；取消 → 不发送，快照不变化 | 01、03～05 |
| TC-BOSS-02 身份切换 | 两个 owner、设备离线、切换平台账号、撤销连接 → 拒绝越权及旧身份授权，提示重连 | 02、10 |
| TC-BOSS-03 分动作核验 | 模拟沟通成功、文字成功、附件待许可／失败／确认 → 状态及证据分别准确 | 06、11 |
| TC-BOSS-04 未知与并发 | 发送后丢回执、双执行器、延迟确认、重启重连 → unknown 不自动重放，无双重领取 | 07、08 |
| TC-BOSS-05 平台条件 | 模拟失效登录、验证码、限制、岗位关闭及附件要求 → 停止相关发送，明确人工处理 | 09 |
| TC-BOSS-06 清理与降级 | 账户注销、连接撤销、平台不可用 → 不能领取，材料受控；私有保存和备份仍可用 | 10、12 |
| TC-BOSS-07 真实平台闭环 | 用户明确授权的账号、岗位及发送范围 → 逐动作核对平台会话及附件事实，未知如实保留 | 02～11 |

模拟适配器只证明内部状态与故障处理。真实平台闭环须单独验证；没有授权岗位时停留在准备、模拟与只读核查，不发送测试消息。任何平台行为变化均需重新确认适配行为，不能从开源 README 的“apply”推断附件投递成功。
