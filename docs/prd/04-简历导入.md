# 简历导入

唯一来源 design：[设计 02](../design/02-CV制作管理与展示设计.md)。PRD-CV-04。目标验收覆盖本能力全部范围，实施与验证状态见 BACKLOG；列出验收不表示已经通过。

## 1. 用户结果与边界

作为所有者，我希望从已有文件生成可校对的新 CV，减少重填，同时保留原有简历。

范围：格式校验、解析、候选校对、确认另存及取消/失败；格式识别不等于 CV 字段识别，不默认引入 OCR 或 AI。

## 2. 验收条件

- **AC-CV-21**：选择文件前可见支持格式/限额；各支持格式能进入可理解的读取与解析流程。
- **AC-CV-22**：候选字段、正文、警告及未归类文字可核对和调整，不假造学校、公司、日期或成果。
- **AC-CV-23**：确认后另存私有 CV；失败、取消、重复确认不覆盖旧 CV、不生成多份或半份正式 CV，也不自动公开。
- **AC-CV-24**：超限、损坏、不支持、未知备份版本、无文字/扫描 PDF 均给出原因和下一步，不以空结果提示成功。

- **AC-CV-52 核心格式**：CVory v1 JSON 与 Markdown 文件／粘贴按设计支持；JSON 保留结构化条目及资源，Markdown 明示语义范围。猫步／JSON Resume／文字 PDF／DOCX 仅在相应版本映射和校对验收通过后作为扩展开放。
- **AC-CV-53 定点校对**：只改正文、一个字段或一条经历后，其他条目的稳定 ID、学校、公司、日期、链接、显隐及照片均保留；未知内容保留原文及警告。
- **AC-CV-54 受限转换**：Markdown 转换不依赖 AI 或竞品后台；无效嵌套、危险 URL、图片超限及脚本被拒绝或安全降级，服务端再次验证，取消不留正式数据。

## 3. 验证场景

| 场景 | 条件与角色 | 动作 → 可观察结果 | 对应 AC |
| --- | --- | --- | --- |
| TC-CV-11 支持格式导入 | 每种已选格式各有样例 | 读限制、解析、修字段、归类原文 → 可核对且不凭空补造经历 | 21、22 |
| TC-CV-12 导入失败与取消 | 现有 CV、损坏/超限/未知版本/扫描文件 | 失败、取消、重复确认 → 原 CV 不变，无半份/重复/自动公开，有准确替代提示 | 23、24 |
| TC-CV-29 JSON 校对往返 | 含多条结构化经历的真实备份文件 | 导入、只改一段正文、确认、重开并再备份 → 其他字段和条目保持，只有目标正文改变 | 52、53 |
| TC-CV-30 格式与内容边界 | 10 MB 边界、未知格式、脚本及危险链接 | 核心格式断开模型依赖仍可转换；异常文件得到明确提示，原数据不变；扩展未通过不展示为支持 | 52、54 |
