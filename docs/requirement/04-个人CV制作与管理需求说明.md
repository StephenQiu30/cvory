## 1. 目标与范围

项目同时提供两种使用方式：**本人使用的 CV 制作管理工具、访客访问的个人简历展示网站**。本人能够编写和维护 CV、管理不同用途的版本、调整少量模板、导出 PDF，并将选定的简历信息展示为可直接访问的网页。

两者共用 CV 内容，不维护另一套个人资料。核心闭环是：**新建、导入或复制 CV → 编辑校对 → 调整模板 → 预览并保存 → 导出，或选择公开内容并更新展示网站**。制作管理与在线展示都属于 MVP 核心范围。

完整关系是：**CV 是私有编辑对象；用途版本是独立 CV 副本；模板决定表现；导入产生新的候选草稿；PDF/Markdown/备份是导出产物；展示网站呈现所选 CV 的公开内容**。修改导出文件不会回写 CV，保存草稿也不等于发布。

| 范围 | 确认程度 |
| --- | --- |
| 个人 CV 制作、版本管理、模板调整和 PDF 导出 | 负责人明确要求 |
| 简历导入、导出与用户友好的制作管理流程 | 负责人明确强调；文件类型、校对与错误处理为下文 MVP 建议 |
| 网站同时展示本人的个人简历信息，访客可阅读 | 负责人明确要求；公开版本、字段和发布方式为本文细化建议 |
| 用富文本组件编辑内容，使用 Markdown 语法表达和展示部分内容 | 负责人明确要求；语法子集、转换与保存方式为本文细化建议 |
| 个人自用、少量模板、保持简单 | 已确认约束；模板数量未明确 |
| 名称「简序 · CVory」、B 方案图形、黑白灰与 Geist | 负责人明确选择；具体色值、尺寸、中文字体及图形精修见 DESIGN 中的建议基线 |
| 字段清单、自动保存、独立副本、历史恢复、导出和公开更新规则 | 下文为建议行为，未逐项确认 |
| Next.js、Tiptap 方向 | 负责人提出的技术方向；Geist 使用已确认，具体工程组合、兼容版本、中文字体和部署方式仍为建议 |
| 完整 PRD、实施计划 | 当前不展开 |

AI 生成/翻译/纠错、职位与投递、模拟面试、社区、会员支付、多人协作、模板市场、通用画布不属于范围。截图中的相关按钮仅是竞品入口，不自动成为我们的需求。

## 2. 使用方式与工作界面

参与者包括站点所有者和公开访客。所有者维护 CV、导出文件并决定公开内容；访客无需登录即可阅读已公开的简历，不能进入管理区或修改内容。建议以桌面制作和排版为主，展示网站同时适配电脑与手机。

对外可访问的展示网站是明确目标；管理工具是否也部署在线、是否需要跨设备编辑仍待定。若在线管理，必须校验所有者身份，不开放其他人注册或编辑；若本地管理，则需把选定内容更新到可公开访问的网站，不能用仅存在本机的预览代替展示网站。

保留三个主要界面，公开内容选择与发布可并入编辑预览，不必建立额外发布后台：

- **我的 CV：** 新建、导入、继续编辑、复制、改名、导出、删除；每份 CV 显示名称、更新时间、模板及当前公开来源标识。操作使用文字或可辨识提示，不能只靠无标签图标。
- **编辑与预览：** 选择模块，填写结构化字段及富文本描述，调整模板与排版，查看分页，保存并导出 PDF。
- **个人简历展示页：** 通过稳定网址展示选定版本的个人信息、简介、教育、工作、项目、技能等公开内容，支持手机阅读与有效链接访问。

提供的老鱼截图可作为交互参考：模块导航、内容编辑、预览与样式工具分区；图中能看到模块开关、字段输入、字体/字号/行距、模板风格、间距和导出入口。无需照搬三栏尺寸和全部模块。截图只说明当时可见状态，不证明保存、格式切换或 PDF 结果已经验证；文档不复制其中的个人资料值。

### 2.1 MVP 的主要使用路径

| 起点 | 用户操作与反馈 | 得到的结果 |
| --- | --- | --- |
| 第一次进入，尚无 CV | 明确提供“新建 CV”和“导入已有简历”；用简短说明区分，不混入 AI、付费或招聘入口 | 能开始制作，不必先理解模板体系 |
| 新建 | 选择默认/少量模板后进入编辑；先填写姓名及主要经历，可随时保存，不要求先填完全部模块 | 可继续维护的私有草稿 |
| 已有文件 | 查看支持格式，上传/选择文件，看到读取和解析状态，校对字段及未归类内容，确认后另存 | 一份新的 CV，不覆盖现有版本 |
| 日常维护 | 从列表继续编辑；模块切换保留输入，点击预览中的模块可定位编辑区，保存状态始终可见 | 保存可靠、当前编辑对象清楚 |
| 为某岗位调整 | 复制已有 CV，命名新用途，再调整正文与模板 | 原件和副本独立，列表中容易区分 |
| 准备投递 | 检查页数与溢出，导出 PDF，看到生成中/成功/失败及重试 | 内容与所选版本一致的文件 |
| 需要备份或转移 | 导出完整备份或 Markdown，明确两者保留能力不同 | 能恢复原 CV，或复用其文本内容 |
| 对外展示 | 选择已保存 CV、公开字段并预览，明确发布；访客阅读网页 | 固定网址下的当前公开结果 |

### 2.2 让流程简单、可恢复

编辑界面采用“模块导航、内容输入、预览/样式”的职责分区，但不把固定三栏作为前置要求。窄屏可切换编辑/预览，保留当前模块和滚动位置；公开展示必须适配手机，手机完整编辑深度待确认。

首次制作建议按“基本资料 → 主要经历/技能 → 样式与分页 → 导出/展示”引导，允许跳过可选模块。默认内容只能是明确标记的占位示例，不能在导出中混入假经历；不强制完成度评分、复杂向导或入门教程。

新建、导入、导出期间显示正在处理的阶段，防止重复点击产生多个对象；取消导入不留半份 CV，取消样式面板不改变原样式。错误消息说明问题所在和下一步，如“文件没有可读取文字，请改用文字版 PDF 或粘贴文本”，不只显示错误码。

删除与恢复默认要说明影响范围，保留取消入口。富文本工具有清楚名称与键盘焦点；撤销/重做不改变其他版本。暂不增加多选批量管理、收藏模板、复杂筛选或用量上限，少量 CV 用名称和更新时间即可找到。

## 3. CV 制作与内容组织

### 3.1 结构化字段与描述正文

简历不能只有一整块富文本：姓名、日期、公司、职位等字段需要独立管理，方便模板切换与统一排版；职责、成果、简介等需要表达层次的正文使用富文本。

| 内容模块 | 建议的结构化字段 | 富文本 / Markdown 内容 |
| --- | --- | --- |
| 基本资料 | 姓名、电话、邮箱、所在地、链接、可选头像 | 不强制富文本；字段可选、可隐藏，姓名作为识别信息 |
| 求职意向 | 目标职位、期望地点、当前状态 | 可选，不要求所有 CV 都填写 |
| 教育经历 | 学校、专业、学历、起止日期 | 学习成果、奖项与补充说明 |
| 工作经历 | 公司、职位、起止日期、可选地点 | 职责、工作成果、技术与项目贡献 |
| 项目经历 | 项目名称、角色、起止日期、可选链接 | 项目背景、本人职责、成果 |
| 专业技能 | 可选分类名称 | 技能说明和要点列表 |
| 个人简介 | 模块标题 | 简介段落 |
| 补充模块 | 建议一个可改名的通用模块、可选条目名称和日期 | 荣誉、研究或其他经历，不必为每种场景开发专用模块 |

建议支持模块及重复条目的增加、编辑、删除、排序；支持隐藏模块及可选字段。**隐藏只影响呈现，不删除内容**。删除应明确对象并确认。模板负责排版顺序和列布局，不能因为某模板不展示某字段就清除数据。

日期允许“至今”；起止关系不合理时提示。空的可选字段不输出空标签、图标或占位符。头像可替换、移除并保持比例；是否必须提供裁剪工具待实际需要，不建设素材库。

### 3.2 编辑反馈与保存

建议编辑后自动保存，辅以明确的“未保存、保存中、已保存、保存失败”状态及手动重试。防抖间隔是实现参数，不将竞品代码中的约 3 秒直接定义为产品要求。

只有持久化成功才显示已保存。失败时保留输入，关闭或离开有未保存内容时提醒；中文输入法组合输入期间不应触发格式转换、打断光标或被重新渲染覆盖。旧保存请求不能覆盖更新内容，多标签冲突需提示而非静默覆盖。

重新打开 CV 后，结构化字段、正文格式、模块顺序、隐藏状态、模板和样式都应保留。撤销/重做作用于当前编辑，不能代替历史版本恢复。

### 3.3 简历导入与人工校对

导入是 MVP 核心流程。**文件能转成文字、能转成富文本、能识别为 CV 字段，是三个不同结果**，不能将文件上传成功当作简历导入成功。

建议 MVP 支持范围如下；这是待确认的格式范围，不是现有产品已经实现：

| 格式 | 建议导入结果 | 保真与处理边界 |
| --- | --- | --- |
| 本工具 JSON 备份 | 恢复完整 CV 内容、富文本、模板及有效样式、模块顺序和隐藏状态 | 校验格式版本与资源引用；不导入账号凭据，不自动恢复公开发布；缺模板/头像需提示与可选替代 |
| Markdown / TXT | 解析支持的正文语法，按标题或用户选择归入模块 | 标题/信息行可能是字段候选，不猜造公司、日期或成果；纯文本粘贴作为可靠备用入口 |
| DOCX | 提取文字、段落、基础列表和链接，供用户校对并归入 CV | 不承诺恢复原字体、浮动元素、分栏和全部表格；旧 `.doc` 不是同一格式，首版不承诺支持 |
| 含文字层的 PDF | 提取文字及可识别链接，生成可校对的候选内容 | 阅读顺序、栏位、断行可能错误；必须确认，不承诺复刻原版式 |
| 扫描 PDF / JPG / PNG | 首版建议不做 OCR，明确提示不支持并提供文字替代方式 | 不能返回空内容却提示成功；后续有实际需求再单独评估 |

建议流程：**选择文件 → 检查类型/大小/可读性 → 解析 → 校对候选字段与正文 → 选择模板/名称 → 确认创建私有 CV**。上传前可见格式和大小限制，实际阈值实现前确定；不是让用户失败后才知道限制。

解析后展示识别出的模块与未归类内容，不支持或丢失的格式有说明，原文可对照。用户能够改错、补字段、调整模块顺序、将未归类段落放回正文。不能假造经历、自动润色或静默删除未识别文字。解析结果未校对前不得自动发布；再次选择文件应明确替换候选内容还是重新开始。

完成确认才生成新 CV；导入失败或取消不改已有 CV。重复确认不能创建多份；不以同名文件覆盖已有版本。原文件及候选结果只供本次校对，不默认永久保存或交给第三方 AI/文档服务。是否接入外部转换服务需单独选择，不因使用 Tiptap 就默认发生。

## 4. 富文本与 Markdown 的关系

### 4.1 编辑体验

富文本是主要编辑方式：在工作、项目、技能和简介等正文区域，能够直接输入并通过工具栏应用格式。Markdown 是同一段内容的快捷表达和展示语法，不要求把整份 CV 改写成 Markdown 文件。

建议同时支持：

1. 用工具栏设置加粗、斜体、列表、链接和行内代码。
2. 在正文输入相应 Markdown 写法，识别后呈现对应格式；如 `**重点成果**`、`- 成果要点`、`[项目链接](https://example.com)`。
3. 粘贴受支持的 Markdown 段落时按明确规则转换；不确定的内容先提示，保留原输入，不能转换失败后覆盖正文。
4. 编辑器、只读预览、公开展示页和 PDF 对同一内容表达相同含义：加粗仍为加粗，列表层级及编号不变，链接标题和目标对应，Markdown 标记不会误当作普通正文打印。公开展示只使用被选择公开的内容，不要求与所有者完整 PDF 包含相同字段。

当前不要求整份简历的 Markdown 源码编辑器。若需要“查看或修改当前描述块的 Markdown 源码”，应作为同一内容的另一视图单独确认，不建设第二份独立维护的数据。

### 4.2 建议支持的语法子集

| 能力 | Markdown 表达 | 预期呈现与边界 |
| --- | --- | --- |
| 普通段落 | 文本、空行 | 保留段落及有意插入的换行，不无限累积空段撑版 |
| 加粗 / 斜体 | `**重点**`、`*强调*` | 与工具栏效果一致，可取消格式 |
| 无序列表 | `- 要点` | 可增删列表项；建议最多两层嵌套 |
| 有序列表 | `1. 步骤` | 保留顺序与可见编号，换页不随意重置 |
| 链接 | `[名称](https://example.com)` | 可查看、修改和移除；禁止脚本链接，PDF 保留有效跳转 |
| 行内代码 | 单个反引号包裹技术名称 | 用于短技术标识；长文本仍可合理换行，不能撑出纸张 |

首版建议不支持任意 HTML/CSS、脚本、嵌入网页、正文远程图片、复杂表格、公式、图表、脚注和代码块。模块标题由结构化模块管理，正文不额外开放任意级别标题；分页不通过 Markdown 分隔线表达。是否需要上述能力应由具体 CV 样例驱动。

不支持的格式必须可预期处理：保留文字并提示不支持，或在覆盖前让使用者选择纯文本粘贴；不能无提示删除段落、列表项、链接或其他语义。粘贴网页内容时移除隐藏样式与危险内容，不导入整页布局。

### 4.3 保存和转换要求

正文应只有一个权威的可编辑内容源。富文本、Markdown 和预览之间的转换围绕这份内容进行，不能让“编辑器内容”和“Markdown 文本”各自自动保存并互相覆盖。

在声明支持的子集内，保存后重开、富文本转 Markdown 再恢复，文字、段落、强调、列表与链接语义应保持一致。允许 Markdown 字符串规范化，例如统一列表标记或空行；不要求逐字符保留原写法，也不能把这种规范化当作修改了简历事实。

正文格式与模板样式分开：颜色、字号、字体、行距、对齐和页边距由模板统一控制；Markdown 不承载整个简历布局。模板切换不能让正文格式、模块内容或列表关系丢失。

## 5. CV 版本管理

版本管理需要区分两种需求，不能把自动保存都叫作历史版本。

| 概念 | 使用场景 | 建议范围 |
| --- | --- | --- |
| 独立用途版本 | 通用 CV、某岗位 CV、中英文 CV | 首版以命名的独立副本管理；内容手工维护，不附带自动翻译 |
| 修订历史 | 恢复同一 CV 某次修改前的内容 | 是否需要首版提供历史列表、命名快照和恢复待确认 |
| 编辑撤销 / 重做 | 撤销正在编辑的一次操作 | 编辑便利能力，不承诺跨会话恢复 |
| 导出快照 | 明确一次 PDF 来自什么内容与样式 | 导出过程的一致性要求，不自动增加历史版本中心 |
| 公开展示版本 | 决定访客当前看到哪份 CV 的哪些内容 | 建议从一个已保存 CV 生成当前公开内容，不公开全部版本列表 |

建议“我的 CV”支持新建、复制、命名、改名、打开和删除。复制时保留完整内容、富文本、模板、样式与显示状态；随后修改副本不影响原件，修改原件也不追改副本。

列表至少能区分版本名称、最后保存时间、模板及是否为当前展示来源。内部稳定标识不依赖名称，名称相同不能覆盖另一份 CV。删除前提示且可取消；若是当前公开展示的来源，建议先切换展示来源或撤回公开，再允许删除，不能顺带静默删掉网站内容。是否提供回收站不作为默认要求。

如果确认需要修订历史，后续再规定快照创建时机、保留范围和恢复规则；恢复前应保留当前内容，避免把“恢复”变成另一种丢失。当前不增加分支、差异合并或复杂版本树。

## 6. 模板选择与调整

建议首版提供 2～3 个可区分的模板，如简洁单栏、紧凑单栏或侧栏布局，具体数量及款式待确认。模板共用 CV 内容结构，试换模板不需要重填资料。

可调整项建议包括：字体预设、字号、主题色、行距、模块/条目间距、A4 页边距、头像显示及模块顺序/隐藏。参数有合理范围和默认值，支持恢复默认；不开放任意位置拖拽和模板代码编辑。

“保存为我的样式”保存的是基于内置模板的参数预设，支持命名、改名、使用和删除。应用到 CV 时保存该 CV 的有效参数；之后修改/删除预设不能悄然改变已有 CV 或已导出的文件。内置模板不被用户误删。

预览中的模板、字号与间距应与导出采用同一套有效配置。切换单栏/侧栏时允许排版与页数变化，但内容必须完整；长正文、长链接与中文标点不能重叠或溢出。

## 7. PDF 导出

PDF 导出是明确的核心需求。建议从当前 CV 直接触发下载，文件名能识别对应版本；无需建立导出记录中心。若只通过浏览器打印对话框完成，应明确这是交付方式的取舍，不能默认等同于直接下载。

### 7.1 内容与保存一致性

导出前确保当前内容保存成功，并在开始导出时固定该次内容、模板和样式。导出过程中继续编辑，不能生成混合新旧数据的文件；失败时保留编辑状态，允许重试，不提示下载成功。

有未保存内容、保存失败或不能转换的格式时给出明确提示，不悄然导出旧版本。隐藏模块和字段不进入 PDF；空模块、编辑按钮、工具栏、模块开关、水印、浏览器网址及默认时间页眉不应进入成品。

### 7.2 排版与文件质量

- 使用 A4，支持一页与多页，不强制缩小所有文字以塞进一页。
- 显示页数和纸张边界，预览与 PDF 的正文、顺序、格式和有效配置一致；编辑表单不要求与 PDF 外观相同。
- 标题与紧接的正文尽量同页，避免孤立模块标题；一条很长的经历允许跨页，不能为保持整条同页而裁掉文字。正常分页不靠大量空行修补。
- 中文与英文、粗体、列表符号正常显示，长链接合理换行，页边距稳定，不出现文字裁切、覆盖或意外空白页。
- 正文是可选择、搜索、复制的文本，链接可点击，不能把整页截图作为唯一 PDF 内容。
- 字体与头像就绪后再生成文件；跨设备打开不应因缺字体导致乱码或大幅改变排版。

导出的 PDF 应保持本地文件独立可用，不依赖访问私有简历接口才能显示内容。是否显示页码、是否人工分页可按样例评估，当前不增加高级印刷设置。

### 7.3 导出格式与再次使用

建议在一个“导出”入口明确提供用途，不让用户从多个同名按钮猜测：

| 格式 | 用途 | 应说明的限制 |
| --- | --- | --- |
| PDF | 投递、打印和离线阅读；核心必需 | 下载成功不等于内容已校验；不得有平台水印或混入编辑控件 |
| 本工具 JSON 备份 | 恢复、迁移和保留可编辑数据；MVP 建议 | 保留内容、样式与格式版本，不含认证信息；头像/字体等资源的随包或引用方式需明确 |
| Markdown | 复用简历内容、在其他文本工具中修改；MVP 建议 | 基本资料用信息行、模块用标题表达，正文用支持的语法；不保证保存模板、精确分页或所有布局，不能代替完整备份 |

导出后保留当前编辑位置，可重复下载或重试，不重复新建 CV。JSON 再导入用于核对可恢复性；Markdown 再导入用于核对正文语义，不承诺与 JSON 一样完整还原布局。Word/PNG 导出不作为默认 MVP 要求，避免为模仿竞品增加第二套版式维护。

## 8. 个人简历展示网站

### 8.1 展示内容与网页体验

访客通过固定网址直接阅读本人简历，不需要账户，也不需要先下载 PDF。建议一个站点只展示一份当前选定的简历，内容包括基本资料、个人简介及所选教育、工作、项目、技能等模块。网页标题使用公开姓名及可选职业描述，不把私有版本名称直接暴露给访客。

展示页以网页阅读为目标：手机上正常换行和纵向浏览，长链接不撑出屏幕，侧栏在窄屏合理重排；不能只是把一张 A4 图片缩小。网页与 PDF 可以有不同布局，但同一公开内容的文字、格式和顺序语义应一致。可继承 CV 的主题色、字体及模块设置，无需增加另一套通用页面设计器。

### 8.2 共用内容与公开更新

建议由所有者选择一个已保存的 CV 作为展示来源，选择公开模块与字段，查看访客视角的预览后明确发布。内容来自现有 CV，不在展示页重新填写一份人物资料。

建议保存草稿与更新网站分开：编辑或自动保存 CV 不立即改变公开页面；再次发布才更新。发布时固定内容及有效样式，成功后整体替换当前展示，失败保留上一次公开结果，不能混合新旧字段。一个当前公开结果即可，不建设复杂发布历史或审批流程。

所有者应能识别当前展示来源、是否存在未发布修改，并可切换来源或撤回展示。更新后网址保持稳定；撤回后本站公开页面及数据入口不再返回这份个人简历，提示暂未公开即可。第三方已下载或缓存的副本不属于本站可撤回范围。

### 8.3 字段公开与访问边界

CV 内的内容隐藏规则继续生效；另外允许“在本人 CV / PDF 保留，但网页不公开”的字段选择，例如电话、邮箱或求职状态。联系方式建议默认不公开，所有者选择后才展示。网页隐藏不能删除原始 CV 数据。

访客只能获得已发布的公开内容，不能通过页面源码、初始数据、公开资源或匿名接口读到私人联系方式、草稿、版本列表或其他 CV。不能只在页面上隐藏字段，却仍向浏览器发送完整 CV。管理区及写操作必须与公开阅读分开。

访客 PDF 下载是否提供待确认。若提供，只能下载与公开展示匹配的 PDF，不能连接到所有者完整 CV 的私有导出；关闭该入口后不应继续从本站公开文件地址取得私人版本。所有者仍可在管理区导出完整 CV。

## 9. 应重点核对的结果与待定项

这部分用于检查需求是否说清楚，不展开测试计划：

| 关注结果 | 应能判断的行为 |
| --- | --- |
| 内容可维护 | 多段经历和富文本保存、关闭、重开后内容与格式一致 |
| 首次制作友好 | 空状态可直接新建或导入，可选字段可跳过，默认模板即可继续，不需要先完成复杂设置 |
| 导入可校对 | 类型/大小/无文字错误明确，候选内容可修正与归类；确认后创建新 CV，失败/取消不覆盖旧版本 |
| Markdown 可用 | 工具栏与 Markdown 写法表达相同结果，不支持格式有提示，不静默丢内容 |
| 版本相互隔离 | 复制后修改任一 CV，另一份的内容和样式不变 |
| 模板不破坏内容 | 切换全部内置模板，隐藏后恢复模块，正文与列表仍完整 |
| 保存可信 | 故障、中文输入和重复保存不会制造假成功或旧内容覆盖新内容 |
| PDF 可投递 | 使用包含长中文、链接、列表和多页经历的样例，实际文件可阅读、选择、复制和跳转 |
| 导出可复用 | JSON 能恢复支持版本的完整 CV；Markdown 能复用支持语法的内容；下载失败可重试，不制造假成功 |
| 网站可展示 | 访客无需登录，通过稳定网址在电脑及手机阅读选定的公开简历，内容不是不可读的 A4 缩略图 |
| 公开内容可控 | 修改草稿不自动公开；发布更新完整，失败保留旧结果；未选择公开的字段不出现在匿名可获得的数据中 |
| 制作与展示共用资料 | 修改来源 CV 后可预览并发布，不必在展示页重录个人资料；其他用途版本仍保持私有 |

仍需确认的细节包括：**导入格式与文件限制，DOCX/PDF 的解析路径；JSON/Markdown 导出的范围；修订历史是否首版提供；模板数量；描述块源码视图；管理工具部署方式；公开字段与显式发布；访客 PDF 下载**。制作、导入导出、版本管理、模板调整与公开展示属于明确需求，具体格式范围及交互细化仍是建议，不能将整体导入能力推到 MVP 之外。

## 10. 技术选型建议

本节是候选方案及取舍，不是已经采纳的工程合同，不在需求正文中绑定依赖版本。

### 10.1 推荐组合与取舍

建议以 **Next.js App Router + React + TypeScript、Tailwind CSS + shadcn/ui、Tiptap、Drizzle、Chromium 打印**构成一个应用。对于本人使用、少量模板的范围，这个组合可以共用内容结构、校验、模板和公开渲染，不需要额外维护一套 Java/Python 后端。该判断是针对当前范围的建议，不是竞品架构结论。

公开展示优先使用 Server Components 或静态生成；编辑器和样式调整留在 Client Components，并只在制作页面加载编辑器。公开访客不需要下载整个 Tiptap 编辑环境，也不能收到未经筛选的私有 CV。Next.js 的服务端/客户端边界与 Tiptap SSR 初始化方式需要一起处理。[T8][T9]

| 层次 | 建议 | 理由与边界 |
| --- | --- | --- |
| 应用 | 按负责人方向优先使用 Next.js App Router + React + TypeScript 单应用 | Route Handlers / Server Actions 承担必要服务端操作，每个写入口校验所有者身份；Next.js 与 Vercel 托管分开决定 [T4][T8] |
| 界面组件 | Tailwind CSS + shadcn/ui，选择一套一致的底层交互原语，优先评估 Radix 方案 | 用语义变量实现 DESIGN 的黑白灰，不并行引入多个整套 UI 库；组件源代码可调整，但可访问性仍需实际验证 [T10] |
| 字体 | Geist 用于界面及西文；建议 Noto Sans SC 补中文，Geist Mono 按需用于短代码 | 用 next/font 或固定本地字体文件，保证可控加载；Geist 声明覆盖没有 CJK，中西文、字重及 PDF 字体需一致验证；中文字体尚未选定 [T5][T11] |
| 富文本 | 按负责人方向优先评估 Tiptap 的受限节点/标记、工具栏及输入规则 | 只启用本文支持格式，不引入协作/AI。组件选择不等于自动获得 CV 字段识别或 DOCX/PDF 导入 |
| Markdown | 评估官方 `@tiptap/markdown`；固定语法子集并验证往返转换 | 官方有 Markdown 解析与序列化接口，但存在已知限制，不能承诺任意富文本/HTML 都无损转换 [T1] |
| 权威内容 | 建议结构化 CV 字段 + 富文本 JSON 为持久化源，带格式版本 | Markdown 是受控转换格式，渲染结果是派生产物；如缓存 Markdown，不能将其作为第二个可编辑来源。官方推荐 JSON 保存编辑文档 [T2] |
| 展示 | React 模板 + HTML/CSS；优先评估 Tiptap Static Renderer 从富文本 JSON 直接生成受控内容 | Markdown 输入先转换到相同内容结构；预览、网页与打印共用受限节点映射，不强制每次先转 Markdown 再转回 HTML，减少语义损失；公开页不受 A4 尺寸约束 [T9] |
| 公开数据 | 从来源 CV 生成独立的当前公开结果，保留来源关联及内容/样式版本 | 管理数据是编辑源，公开结果是派生内容；发布失败保留旧结果。服务端或静态生成阶段排除私人字段，不把完整 CV 发给公开页面再隐藏 |
| 数据 | 单实例持久磁盘条件下 SQLite + Drizzle；Vercel 托管时比较远端 PostgreSQL + Drizzle | 数据库、头像等资源需要备份；不把函数临时文件或浏览器缓存当永久数据库。更换数据库涉及驱动和迁移，不能承诺零成本切换 [T7][T12] |
| PDF | 若要求直接下载，优先评估 Playwright + Chromium 复用打印视图 | 使用同一份内容和有效配置，等待字体/图片，固定 A4；浏览器打印可作替代方式，但有用户设置差异 [T3] |
| 文件解析 | JSON 备份做结构校验；Markdown/TXT 受限解析；DOCX 评估 Mammoth，文字层 PDF 评估 PDF.js | 格式解析与经历字段归类分开，必须保留人工校对；DOCX 不保真原版式，PDF 不承诺正确栏位顺序，不处理扫描件 OCR。Tiptap 的独立转换服务不等于 core，解析库也不自动识别 CV 字段 [T6][T13] |
| 客户端状态 | 从 React 局部状态与 Tiptap 编辑器状态开始 | 持久数据由服务端保存；只有明确跨区共享需要时再评估状态库，不默认增加全局 store 或第二份 Markdown 状态 |

官方资料说明：Tiptap 的 Markdown 转换存在不能表达全部富文本结构的限制；超出编辑器 schema 的 HTML 内容也可能被丢弃。因此我们的受限格式与失败提示是必要产品规则，采用组件并不会自动满足这些规则。需要用真实中文经历、列表、链接和跨页内容验证，不能只看英文演示。[T1][T2]

候选内容流是：**结构化字段与富文本 JSON → 受控只读渲染 → CV 模板预览 / PDF 打印视图**。Markdown 作为输入/导入/导出的语法边界，转换到同一份 JSON，渲染后仍表达对应语义；不要求每次展示强制经过有损往返。公开展示增加**选择公开字段 → 生成公开结果 → 响应式网页**的分支。列表、换行、链接及行内代码在各环节需要一致，未知节点必须提示，不静默丢失。当前不实现代码或依赖集成。

### 10.2 部署与 PDF 的选择条件

| 方式 | 建议组合 | 适用条件与代价 |
| --- | --- | --- |
| 自有持久磁盘的单实例 Node 服务 | Next.js + SQLite/Drizzle + 同机 Chromium；头像在持久目录 | 如果可接受维护一个服务，这是当前自用范围下优先比较的简单方案；需要系统更新、备份、进程恢复及浏览器资源限制 |
| Vercel 在线托管 | Next.js + 远端 PostgreSQL/Drizzle + 持久对象存储；Chromium 运行适配另验 | 如果更看重托管部署体验，这是合理选择；需要远端存储及浏览器包体/执行限制适配，不承诺无额外服务或费用 |

Logo 与 Vercel 视觉参考不构成部署选择。无论哪种方式，单所有者管理入口都需身份校验；具体认证方案待管理工具部署方式确定，不扩展为多用户账号产品。

若采用 Vercel Functions，不能以函数本地 SQLite 文件承担永久持久化；需选择远端数据库。Chromium PDF 需要适配运行包体、字体、执行与响应限制，不能承诺零配置；若选有持久磁盘的单实例 Node 服务，SQLite 路径仍可比较。上传解析与 PDF 生成是否使用外部服务另定，不把技术候选隐含成新增付费依赖。[T7]

PDF 建议复用 HTML/CSS 打印模板，固定同一份保存快照、字体和资源，并在 Chromium 中等待加载后生成。截图拼接会损失文字可选性，不作为默认导出；独立 PDF 布局引擎可能需要另维护排版，也不作为首选。分页、页数、长链接与中文字体嵌入仍需真实样例验证。浏览器打印可作备用入口，不能把它当作直接下载质量已验证。[T3]

- T10：[shadcn/ui 主题](https://ui.shadcn.com/docs/theming)。官方支持语义颜色变量；组件原语与版本在集成前确定，不把默认配色当作负责人已经确认的 token。
- T11：[Noto CJK 官方项目](https://github.com/notofonts/noto-cjk)。中文字体需选定具体文件、覆盖和授权记录，未下载或嵌入字体。
- T12：[Drizzle 官方说明](https://orm.drizzle.team/docs/overview)。类型化 SQL 与 schema 迁移适合作为候选，不代表数据库已经选定。
- T13：[Mammoth](https://github.com/mwilliamson/mammoth.js)、[PDF.js](https://mozilla.github.io/pdf.js/)。仅作为 DOCX 内容转换与 PDF 解析候选；导入后的安全过滤、文本顺序与字段归类仍属于本项目工作。
- 框架、存储、部署与 PDF 路径的官方来源及逆向边界见[背景调研](../research/02-老鱼简历功能逆向与CV技术选型.md#5-技术选型建议)，不把竞品前端实现当成我们的既定选型。
