# 个人 CV 制作、管理、展示与投递需求

最初诉求见[原始需求 01](01-个人简历网站原始需求.md)。本文是完整业务目标，覆盖已有能力与目标能力，对应唯一的[产品设计 02](../design/02-CV制作管理与展示设计.md)。需求存在不表示功能已实现或通过验收，状态只在 [BACKLOG](../../BACKLOG.md) 维护。

## 1. 产品目标与使用者

简序 · CVory 为长期维护经历、制作不同用途简历的用户，提供录入、管理、输出、展示和投递的连续流程，减少在多个工具之间反复填写经历。保持简单，使用少量模板，不建设完整求职平台。

- **所有者**：注册和管理账户，制作不同用途的 CV，备份数据，发布选定内容及控制投递。不同账户的私有数据隔离。
- **访客**：无需注册，通过网址阅读明确发布的内容，不接触私有数据和管理功能。
- **求职用户**：使用自己的 BOSS 直聘账户，将选定简历用于明确选择的岗位，了解实际执行结果。

用户可以只制作、只导出或只展示，不要求使用全部能力。制作、保存和备份不依赖 AI 或招聘平台在线。

## 2. 范围与决策边界

已明确方向是多用户、少量模板、版本及样式管理、导入导出、个人展示，以及自主实现 BOSS 投递并允许基于开源改造。邮箱验证、恢复及注销按现行设计纳入账户生命周期。

自动保存与恢复、历史快照、无损校对、统一输出及投递结果核验是调研转化的目标要求，纳入评审和实施；不表示负责人逐项确认全部交互或技术方案，不表示现有代码已具备这些能力。技术取舍回设计，验收回 PRD。

第 3 节定义核心完整闭环；跨格式迁移另列扩展目标。不以扩展未完成为由省略核心流程，也不把竞品全部功能纳入产品。

## 3. 完整能力要求

### 3.1 账户访问与生命周期

用户可用邮箱密码注册、登录，维护显示名及账户头像，退出后不能继续访问私有内容。会话过期保留输入，同账户重登可以恢复，不将草稿交给另一账户。账户资料与每份 CV 的人物资料分别维护。

提供邮箱验证、密码修改及符合条件的密码找回。未验证用户能制作、保存和导出私有 CV，发布须验证邮箱。过期、重放、发送失败有明确下一步，“已提交发信”不表示“已收到邮件”；不能仅凭邮箱控制权接管未验证账户中的既有简历。

用户可先备份再注销，了解等待、取消、清理、公开页面及备份处理；注销期间限制访问，清理失败不报告完成。

### 3.2 简历库与开始制作

空列表可直接新建、选模板或导入。列表显示名称、真实封面、更新时间及公开关联，提供编辑、改名、复制、下载、公开管理和删除。同名不覆盖，不引入未经定义的数量配额。模板示例只用于预览，新建得到空白 CV；桌面和手机保留相同业务入口。

### 3.3 结构化制作与正文

支持基本信息、教育、工作、项目、技能、简介及可改名补充模块；重复经历可增删、排序、编辑日期。模块、字段和照片可隐藏后恢复，隐藏不删内容。

姓名、学校、公司、日期保留结构化字段，职责与成果支持段落、强调、列表、链接和行内代码。工具栏、Markdown 和粘贴写入同一正文；中文输入、键盘、撤销和重做可用，不支持格式有提示并保留可读文字。

### 3.4 保存、离开与恢复

提供自动和手动保存，区分未保存、保存中、已保存、失败及冲突。服务端持久化成功才算已保存；保存期间的新输入不被旧响应覆盖或误确认。

返回、刷新、关闭、断网及会话过期时帮助保留和恢复输入。候选说明所属 CV、时间及与服务器内容的关系，用户可恢复、另存或放弃，不静默覆盖远端新内容。浏览器存储不可用或被清除时说明恢复限制。

### 3.5 用途版本与历史快照

用户可按用途命名、复制独立 CV，保留内容、显隐、照片和有效样式，后续互不影响。删除说明对象及影响，当前公开来源不可无声删除。

用途副本用于独立编辑，历史快照用于找回已保存内容。可查看可用快照并恢复为新副本，保留当前内容，不改变公开页或既有投递。保留范围可理解，不承诺无限历史，不建设分支合并。

### 3.6 模板与个人样式

提供标准单栏、紧凑单栏、时间索引三套模板，可调整受支持字体、字号、行距、间距、页边距和配色。支持试用、应用、取消、恢复默认及预设的保存、改名和删除。

模板只改变排版，切换不丢字段及隐藏内容。CV 保存有效样式，预设后续修改不追改已有 CV。编辑预览和最终文件关系清楚，精确分页以同一版本生成的 PDF 为准。

### 3.7 文件导入与校对

核心支持 CVory JSON 备份和 Markdown 文件或粘贴。先展示格式、大小及保真边界，解析后核对字段、经历、正文、未归类文字和警告，确认才另存私有 CV。

改正文不能清空学校、公司、日期、链接或其他经历。不确定内容留给用户处理，不编造经历或把空解析当成功。失败、取消及重复确认不覆盖原 CV，不产生半份或多份正式简历，不自动公开。

扩展目标为有版本映射的猫步／JSON Resume 数据、文字型 PDF 及 DOCX 内容迁移。每种格式单独声明范围，通过校对验收才可标为支持；不承诺还原任意版式，不默认加入扫描件 OCR。

### 3.8 备份与 Markdown 交换

JSON 是单份 CV 的可恢复备份，保留声明支持的字段、正文、顺序、显隐、样式和照片，脱离原站私有链接仍可恢复。不含认证、验证、发布状态、平台登录态或投递授权。

Markdown 用于正文语义复用，不承诺精确排版和分页。下载明确采用哪个已保存版本，失败可重试，不打断编辑或生成多余 CV；恢复后必须得到可继续编辑的新对象。

### 3.9 PDF 与投递文件

从选定已保存版本生成可离线阅读、投递及打印的 PDF；生成期间的新编辑不改变本次文件。有未保存修改时先明确保存或选择已保存内容，不能悄然下载旧版。

支持 A4 单／多页、中英文、照片、列表及链接；文字可选、可搜、可复制，无裁切、覆盖、异常空页、隐藏字段、控件和水印。字体、照片、生成失败有准确反馈及重试；PDF 不可用时仍可保存和备份。

### 3.10 公开展示与撤回

每账户一个稳定公开地址。从已保存 CV 选择公开字段、预览并明确发布；保存、复制、恢复、导入及投递不自动更新网页。访客在电脑和手机阅读自然重排的文字。

未选字段、私有版本名、其他 CV 和私有照片不进入匿名页面、接口、源码或资源。更新失败保留旧结果，撤回后本站页面、数据、资源及受控缓存停止返回内容，不承诺召回访客已下载副本。

### 3.11 BOSS 直聘自主投递

CVory 自主维护任务、岗位、简历快照、执行适配及结果，可改造合适的开源代码，不以外部 CLI 为唯一产品入口。

用户在自己控制的环境登录 BOSS，选择岗位、固定简历及 PDF，核对招呼文字、附件及发送范围后启动有限任务。提供暂停、停止、重新登录及逐项结果；登录失效、平台限制或验证码时停止相关发送，交还用户处理。

建立沟通、发送招呼、平台确认附件发送分别展示。无证据时显示失败、待处理或结果未知，不以点击或 HTTP 成功代替附件送达，不承诺已读、回复或录用。结果未知先核查，不自动重发。

重复提交、断线、重启不重复已完成动作。新编辑不追改执行中或已执行的快照；导入、备份、公开操作不授予投递权限。首期仅 BOSS，不包含批量海投或验证码绕过。

## 4. 完整用户旅程

1. 注册／登录 → 可恢复的私有工作区；需要发布时验证邮箱。
2. 空白、模板或文件开始 → 录入校对 → 自动／手动保存 → 重开继续编辑。
3. 按用途复制、查看历史、调整模板 → 保存所选版本。
4. 独立选择 JSON／Markdown、PDF、预览发布或 BOSS 岗位投递；一种输出不自动触发另一种。
5. 失败保留输入或固定快照，说明重试及未知状态；可撤回公开、停止投递或恢复历史副本。
6. 更换设备通过备份恢复；结束使用可先备份再注销，了解清理与保留限制。

## 5. 完整可用的判定

以真实结果为准：保存重开一致，备份脱离原站可恢复，实际 PDF 正确，匿名只读取明确发布内容，投递状态有平台证据。页面可打开、接口成功和测试脚本存在不能替代这些结果。

覆盖正常、空、处理中、失败、重试、取消、冲突及权限边界，桌面和手机可操作，键盘及中文输入可用。隔离环境、模拟服务、真实 MySQL、邮件、平台和部署分别留证，未执行不计通过。当前完整链路未经验证，不能认定可靠。

## 6. 不包含与尚待选定的事项

不包含通用 AI 生成／翻译、其他招聘平台、模拟面试、会员支付、社区、多人协作、模板市场、自由画布、博客、访客 PDF 及无限历史。未来 AI 须另行定义目标与候选采纳边界，不能成为基础保存及输出的依赖。

发信供应商、公开域名、部署规模、备份与日志保留、人工支持、历史保留上限、扩展格式版本、BOSS 执行形态和上游基座由设计选定。它们影响对应能力实施及发布，不将完整目标退回缺口清单。
