# 个人 CV 制作、管理、展示与投递需求

最初诉求见[原始需求 01](01-个人简历网站原始需求.md)。本文是完整业务目标，覆盖已有能力与目标能力，对应唯一的[产品设计 02](../design/02-CV制作管理与展示设计.md)。需求存在不表示功能已实现或通过验收，状态只在 [BACKLOG](../../BACKLOG.md) 维护。

## 1. 产品目标与使用者

简序 · CVory 是面向个人、由使用者自行部署的开源简历与求职工具，提供制作、版本管理、文件交换、首页展示、GitHub 项目展示、AI 分析与 BOSS 插件投递的连续流程。使用少量模板、简单界面；账户隔离服务于每个人自己的资料，不扩展为招聘平台或社区。

- **所有者**：注册和管理账户，制作不同用途的 CV，备份数据，发布选定内容及控制投递。不同账户的私有数据隔离。
- **访客**：无需注册，通过网址阅读明确发布的内容，不接触私有数据和管理功能。
- **求职用户**：使用自己的 BOSS 直聘账户，将选定简历用于明确选择的岗位，了解实际执行结果。

开源许可选定 MIT，允许按其要求修改、分发和商用并保留版权/许可声明；第三方代码与素材的授权单独核对。

部署者使用自己的 GitHub OAuth 应用、存储/域名和 AI 服务账户，配置及数据保存在自己的部署环境；不依赖 CVory 运营方提供账户托管、共享模型额度或代管平台凭据。

用户可以只制作、只导出或只展示，不要求使用全部能力。制作、保存和备份不依赖 AI 或招聘平台在线。

## 2. 范围与决策边界

负责人明确要求：富文本与 Markdown 编辑；导入 MD、DOCX、PDF；导出 PDF、PNG；发布后在项目首页美观、便于查阅地展示；用途版本管理；GitHub 登录与仓库项目展示；按关键词合理投递的 BOSS 浏览器插件，以及简历分析和岗位匹配所需 AI 服务。这些是需求，不因当前代码缺失降为可选扩展。

当前阶段只整理需求、调研与评审服务设计，不编码、不迁移数据、不部署、不进行真实投递。原始需求 01 原文保留；本文吸收负责人明确补充。技术实现、首页路由细节、后续 OCR、具体模型/预算及运行参数分别标为建议或待定，不能将调研建议当成负责人逐项确认。

现有邮箱密码账户属于存量实现；目标使用 GitHub 登录。存量账户如何安全绑定、迁移和结束兼容由设计定义，不自动合并同邮箱账户，也不删除既有资料。历史快照、恢复、隔离与准确输出继续作为质量目标。

## 3. 完整能力要求

### 3.1 账户访问与生命周期

用户使用 GitHub 登录进入自己的工作区，维护显示名与头像，退出后不能访问私有资料。GitHub 不公开邮箱不应阻止新用户制作、保存、导出或明确发布；不额外要求创建本地密码。账户资料与每份 CV 的人物资料分别维护。

会话过期保留输入，同账户重登可恢复，不把草稿交给另一账户。GitHub 授权失败、撤销、用户名改变有清楚处理路径；公开展示读取明确发布的内容，不以 GitHub 实时可用为前提。存量邮箱账户在确认归属后绑定，不能通过邮箱匹配接管。

用户可先备份再注销，了解等待、取消、清理、公开页面及备份处理；注销按相应身份重新核验，清理失败不报告完成。

### 3.2 简历库与开始制作

空列表可直接新建、选模板或导入。列表显示名称、真实封面、更新时间及公开关联，提供编辑、改名、复制、下载、公开管理和删除。同名不覆盖，不引入未经定义的数量配额。模板示例只用于预览，新建得到空白 CV；桌面和手机保留相同业务入口。

### 3.3 结构化制作与正文

支持基本信息、教育、工作、项目、技能、简介及可改名补充模块；重复经历可增删、排序、编辑日期。模块、字段和照片可隐藏后恢复，隐藏不删内容。

姓名、学校、公司、日期保留结构化字段，职责与成果支持段落、强调、列表、链接和行内代码。提供可反复修改与预览的 Markdown 编辑模式，不限于一次性粘贴导入；工具栏、Markdown 和粘贴写入同一正文；中文输入、键盘、撤销和重做可用，不支持格式有提示并保留可读文字。

### 3.4 保存、离开与恢复

提供自动和手动保存，区分未保存、保存中、已保存、失败及冲突。服务端持久化成功才算已保存；保存期间的新输入不被旧响应覆盖或误确认。

返回、刷新、关闭、断网及会话过期时帮助保留和恢复输入。候选说明所属 CV、时间及与服务器内容的关系，用户可恢复、另存或放弃，不静默覆盖远端新内容。浏览器存储不可用或被清除时说明恢复限制。

### 3.5 用途版本与历史快照

用户可按用途命名、复制独立 CV，保留内容、显隐、照片和有效样式，后续互不影响。删除说明对象及影响，当前公开来源不可无声删除。

用途副本用于独立编辑，历史快照用于找回已保存内容。可查看可用快照并恢复为新副本，保留当前内容，不改变公开页或既有投递。保留范围可理解，不承诺无限历史，不建设分支合并。

### 3.6 模板与个人样式

提供标准单栏、紧凑单栏、时间索引三套模板，可调整受支持字体、字号、行距、间距、页边距和配色。支持试用、应用、取消、恢复默认及预设的保存、改名和删除。

模板只改变排版，切换不丢字段及隐藏内容。CV 保存有效样式，预设后续修改不追改已有 CV。编辑预览和最终文件关系清楚，精确分页以同一版本生成的 PDF 为准。

### 3.7 文件导入与校对

必需支持 Markdown（.md）文件或粘贴、DOCX 和 PDF 内容导入，并继续支持 CVory JSON 备份。先展示格式、大小及保真边界，解析后核对字段、经历、正文、未归类文字和警告，确认才另存私有 CV。

改正文不能清空学校、公司、日期、链接或其他经历。不确定内容留给用户处理，不编造经历或把空解析当成功。失败、取消及重复确认不覆盖原 CV，不产生半份或多份正式简历，不自动公开。

DOCX 与 PDF 是核心交付要求：先提取内容，再校对为可继续编辑的 CV，不承诺还原任意版式。PDF 至少覆盖有文字层文件；首期不支持扫描件，检测无文字层后明确提示；OCR 后续再定，不能以空白导入成功。旧 .doc 不混称 DOCX。猫步／JSON Resume 的版本映射仍为扩展。

### 3.8 备份与 Markdown 交换

JSON 是单份 CV 的可恢复备份，保留声明支持的字段、正文、顺序、显隐、样式和照片，脱离原站私有链接仍可恢复。不含认证、验证、发布状态、平台登录态或投递授权。

Markdown 用于正文语义复用，不承诺精确排版和分页。下载明确采用哪个已保存版本，失败可重试，不打断编辑或生成多余 CV；恢复后必须得到可继续编辑的新对象。

### 3.9 PDF、PNG 与投递文件

从选定已保存版本生成可离线阅读、投递及打印的 PDF；生成期间的新编辑不改变本次文件。有未保存修改时先明确保存或选择已保存内容，不能悄然下载旧版。

支持 A4 单／多页、中英文、照片、列表及链接；文字可选、可搜、可复制，无裁切、覆盖、异常空页、隐藏字段、控件和水印。字体、照片、生成失败有准确反馈及重试；PDF 不可用时仍可保存和备份。

PNG 从同一固定内容生成；单页可直接下载，多页按顺序导出图片包，说明尺寸及页数。PNG 用于分享预览，PDF 保留可选文字用于投递；不能只导出首屏或将截图 PDF 冒充文字 PDF。

### 3.10 首页、公开展示与撤回

发布后的个人简历必须能在项目首页展示，便于快速查看简介、技能、经历、项目及联系方式；保留稳定个人地址。首页采用个人主页，展示站主选定的一份公开简历及 GitHub 项目；其他账户数据继续隔离，不汇聚成公开广场。从已保存 CV 选择公开字段、预览并明确发布；保存、复制、恢复、导入及投递不自动更新网页。访客在电脑和手机阅读自然重排的文字。

未选字段、私有版本名、其他 CV 和私有照片不进入匿名页面、接口、源码或资源。更新失败保留旧结果，撤回后本站页面、数据、资源及受控缓存停止返回内容，不承诺召回访客已下载副本。

### 3.11 BOSS 直聘自主投递

CVory 自主维护 BOSS Chrome 插件、关键词偏好、岗位、简历快照、投递任务及结果，可借鉴开源模块。用户可配置职位关键词、排除词、城市、薪资及公司排除等条件，先硬条件筛选，再按需要结合 AI 解释岗位匹配；未知条件保留未知，不偷偷放宽必需条件。

首期只支持 Chrome。用户在 BOSS 官方页面自行上传所选 PDF，CVory 提供固定版本文件及标识供核对；插件只读取/筛选岗位并发送已核对招呼，不代为上传或发送 PDF/PNG。选择固定简历，核对招呼与本次岗位范围后启动有限任务。一次启动可覆盖已确认规则和数量的有限集合，不要求每条重复批准；新增岗位或更改材料须重新核对。提供暂停、停止、重新登录及逐项结果；登录失效、平台限制或验证码时停止相关发送，交还用户处理。

建立沟通、发送招呼与人工 PDF 准备分别展示。PDF 上传如由用户确认，仅显示“用户已确认上传”，不是平台附件送达证明。首期附件发送由用户在平台处理，不以插件招呼成功、点击或 HTTP 成功代替附件送达，不承诺已读、回复或录用。结果未知先核查，不自动重发。

重复提交、断线、重启不重复已完成动作。新编辑不追改执行中或已执行的快照；导入、备份、公开操作不授予投递权限。首期仅 BOSS，不包含批量海投或验证码绕过。

### 3.12 AI 简历分析与岗位辅助

AI 首期仅提供火山引擎、DeepSeek 和 OpenAI 官方服务预设；选择服务商与可用模型，不增加第三方转发平台。用户可选择已保存简历版本进行内容诊断、表达改进、与岗位要求对照及招呼草稿生成。结果给出原文依据、缺失或不确定信息和可操作建议；不编造任职、成果、数字或技能，不把匹配分数当作录用概率。

修改以建议和差异呈现，用户采纳后才更新私有草稿；旧版本已变化时先重新核对。AI 不自动发布、替换投递材料或启动发送。调用前能了解选用模型、发送内容及用量范围；部署者自行填写官方密钥与模型配置，调用由自己的后端发起，费用归属于自己的供应商账户；配置仅本人可管理，密钥不得明文回显或泄露给访客/插件。数据用途与保留边界启用前可知。没有 AI 配置、超时或额度不足时，手工编辑、导入导出、关键词筛选和人工投递材料仍可用。

### 3.13 GitHub 项目展示

登录后可读取并选择自己的公开 GitHub 仓库作为项目素材，展示名称、简介、链接、技术信息及同步时间，允许补充个人职责与成果；不能由仓库热度推断个人贡献。用户选择并确认后纳入简历或首页公开快照，不自动展示所有仓库，不读取私有仓库。

刷新远端信息不覆盖人工整理或直接更新已发布内容。改名、删除、转私有、限流或同步失败有提示和处理入口；已经公开的信息撤回按本站规则处理，不承诺自动追踪远端可见性变化。

## 4. 完整用户旅程

1. GitHub 登录 → 进入可恢复的私有工作区；存量账户经双方身份核验后绑定。
2. 空白、模板、Markdown、DOCX 或 PDF 开始 → 校对 → 富文本/Markdown 编辑 → 保存重开。
3. 按用途复制、查看历史、调整模板，选择 GitHub 项目素材并补充事实 → 保存所选版本。
4. 可选 AI 诊断或岗位匹配 → 阅读依据与差异 → 人工采纳到草稿。
5. 独立选择 JSON/Markdown 备份、PDF/PNG、预览发布到首页，或通过 BOSS 插件按关键词准备投递；一种输出不自动触发另一种。
6. 自行上传 PDF，核对平台账号、岗位集合、固定简历和招呼 → 启动有限沟通/招呼任务 → 分动作查看结果，暂停或停止。
7. 失败保留输入或固定快照；可撤回公开、恢复历史副本、更换设备通过备份恢复，或先备份再注销。

## 5. 完整可用的判定

保存重开一致；富文本与 Markdown 可持续编辑；MD、DOCX、有文字层 PDF 逐格式导入校对成功；PDF/PNG 实际文件完整；备份脱离原站可恢复；首页和个人页只读取明确发布内容与项目；GitHub 登录及身份绑定不会接管他人资料；AI 建议需采纳且可追溯；BOSS 按规则和固定材料执行，结果有相应平台证据。

覆盖正常、空、处理中、失败、重试、取消、冲突及权限边界，桌面和手机可查阅，编辑键盘及中文输入可用。隔离环境、模拟服务、真实 MySQL、GitHub、AI、平台和部署分别留证，未执行不计通过。当前完整链路未经验证，不能认定可靠。

## 6. 不包含与尚待选定的事项

不包含其他招聘平台、无人值守海投、验证码绕过、模拟面试、会员支付、社区、多人协作、模板市场、自由画布、博客、访客 PDF 和无限历史。AI 范围限于简历与岗位辅助，不扩为通用聊天或自动编造经历。

待定项：后续 OCR、三家 AI 的具体模型/预算/数据处理、Chrome 插件分发方式、投递数量/间隔与重复策略、历史和文件保留、公开域名及部署。必需的 GitHub 登录、MD/DOCX/PDF 导入、PDF/PNG 导出、首页展示、BOSS 插件和 AI 能力不因细节待选而移出核心范围。
