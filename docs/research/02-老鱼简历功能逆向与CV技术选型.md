# 老鱼简历功能与 MVP 交互调研证据

调研日期：2026-11-01（Asia/Shanghai）。依据：[原始诉求](../requirement/01-个人简历网站原始需求.md)。本文只保留竞品结论、来源与验证边界；业务范围见[需求 04](../requirement/04-个人CV制作与管理需求说明.md)，技术选择见[产品设计](../design/02-CV制作管理与展示设计.md)。

## 1. 结论

公开页面和脚本支持个人 CV 的创建、复制、编辑、模板调整、保存及导出等功能线索。运行观察与静态观察的边界见下文，产品需求不从竞品入口自动推导为必做。

老鱼的网页与公开脚本能支持部分功能判断，不能还原其完整服务端技术栈。本文不将竞品使用的技术自动作为我们的选择。

## 2. 逆向方式与证据边界

### 2.1 实际浏览器操作

使用 reverse-engineer-anything 的 `capture_browser_scenario` 在临时无头 Chromium 中打开[指定模板详情](https://www.laoyujianli.com/template/1685547340318179330)，等待按钮可见并点击“使用模板”。该匿名场景弹出微信扫码登录，停留详情页，没有进入编辑器。没有扫码、注册、提交或保存任何简历；登录态只读观察见第 2.3 节。

模板页面实际呈现基本信息、教育、技能、工作、项目等示例；包含配色、“使用模板”和“扫码分享”。首页与新建页还可见模板创建、Markdown 和导入入口；这些只证明入口存在，不证明执行成功。

### 2.2 公开前端资源的静态分析

从实际页面 DOM 的脚本标签定位主包，再从主包的 chunk 映射定位简历相关资源，仅以普通 GET 下载公开 JavaScript。读取路由、控件处理函数、配置字段及 API 包装函数；**未执行下载的脚本，未调用简历业务 API，未绕过登录，也未访问管理后台页面**。

REA 对“我的简历”和 Markdown 编辑器两个 chunk 完成语法解析；完整主包的自动分析遇到堆内存限制，不能声称完成全站代码分析。为核对复制与保存逻辑，从原主包按字节范围提取两个完整模块，加惰性对象包装后单独静态分析，保留源文件摘要及范围映射。自动图谱有未解析依赖与语义缺口；对具体处理函数另作定点文本核对。

证据级别：**运行观察**覆盖实际查看的页面及控件；**静态观察**表示已交付前端代码存在相应实现路径；**建议**表示我们的产品取舍。静态实现不能证明线上服务接受请求、写入成功或导出正确。

体验判断基于上述观察：入口较多、图标动作较密、模板区较大，个人工具可突出新建/导入及继续编辑。未实际观察到的导入校对、错误恢复不能当作竞品缺失。具体需求只在[统一说明](../requirement/04-个人CV制作与管理需求说明.md)维护。

上述表格保留脱敏观察及未验证项，不保存个人内容或账号页地址。调研覆盖主要流程问题，没有穷尽全部账号、终端、文件与异常条件。

## 3. 老鱼的个人简历功能

| 功能 | 获得的证据 | 结论及边界 |
| --- | --- | --- |
| 选择模板创建 | 实际点击模板详情“使用模板”后出现扫码登录（E04） | 创建动作存在身份门槛；没有验证创建成功 |
| 我的简历列表 | `/my_resume` 路由与列表 chunk；条目有名称、封面、更新时间，读取列表的代码（E05 / L01） | 静态支持多份简历管理，不等于已读取真实账号列表 |
| 复制 | 列表“复制简历”处理函数调用模块 29731 的 `A4({id})`；该导出映射至 POST `/api/resume/copy`（L01 / E06） | 前端有按简历 ID 复制的实现；新对象内容如何复制、是否共享引用，需要服务端/账号实测 |
| 改名、删除 | 列表存在改名输入与更新处理、删除确认及删除请求；提示删除后不可恢复（L01） | 可以参考明确的对象管理；未验证服务端删除语义 |
| 两类编辑入口 | 路由 `/maker/:id`、`/md_maker/:id` 及对应 chunk；前者有模块编辑，后者有编辑/源码模式（L02 / E05） | 老鱼维护两条编辑路径；我们不必同时建设两套编辑器 |
| 内容模块 | 常规编辑 chunk 中存在教育、技能、工作、项目、个人作品、荣誉、其他经历、研究、简介、自定义模块的处理代码（L02） | 值得借鉴模块化；首版不必提供所有类型 |
| 模块/条目调整 | 有增加、删除、上移/下移、模块列表拖拽及隐藏标记相关处理（L02） | 适合有限顺序与显示控制；不是证明支持任意画布布局 |
| 外观调整 | 字体、字号、行距、主题色、间距、模板风格切换；配置中出现 `fontFamily`、`fontSize`、`lineHeight`、`theme`（L02 / E05） | 可参考少量有边界的参数，不必暴露完整 CSS |
| 内容与样式分开 | 常规模块路径使用 `rawContent.moduleList` 与 `cssConfig`；Markdown 路径分别提交 `mdContent` 与序列化 `cssConfig`（L02 / E06） | 可确认前端分别处理内容和样式；数据库结构未知 |
| 保存与错误状态 | Markdown 模型中内容变化后以 `setTimeout(..., 3e3)` 触发保存；有 pending/saving/saved/invalid/failed，样式保存及离开处理（E06） | 是该 Markdown 路径的静态逻辑；不外推为所有编辑器统一 3 秒，也不证明异常恢复完全可靠 |
| 导出前保存校验 | Markdown 工具栏先检查语法/保存状态；保存失败时阻止继续导出，存在 PDF、PNG 下载路径（E05） | 我们应保证产物来自可识别的内容版本；导出文件质量未验证 |
| 分页与预览 | 常规编辑代码有页数、分页切割提示、插入空行、调整行距及“智能一页”（L02） | 分页是核心工程问题；不应强制把所有内容压成一页 |
| 头像 | 有图片选择、裁剪、上传及删除/替换逻辑（L01 / E05） | 可选基础字段；无需扩展为素材管理平台 |
| 分享 | 页面可见扫码分享；列表/编辑器代码存在分享动作（E03 / L01 / L02） | 可作为后续只读呈现参考；权限、撤回、有效期没有实测 |
| 历史版本 | 已核对列表复制路径与保存模型；未取得历史列表、历史恢复的充分证据 | 不能断言老鱼没有历史；也不能把 `contentVersion` 这样的局部变更计数当作可恢复历史 |

这里的“版本”需区分两件事：**不同用途的 CV 副本**，例如通用版、产品岗位版；**同一 CV 的修订历史**，例如恢复昨天的内容。两者都可能被口头称作版本，但产品与数据成本不同。

### 可复核的三个实现链路

1. **复制：** 列表菜单 → 复制处理函数 → `Fe.A4({id:t.id})` → `Fe` 导入 29731 → `A4` 导出 `v` → `/api/resume/copy` 包装。链路止于客户端请求构造，没有执行请求。
2. **Markdown 保存：** 输入更新 → 更新当前内容及局部变更号 → 语法检查 → pending → 3 秒计时 → `/api/resume/md/edit` 包装 → saved 或 failed。该流程表明前端有状态保护，不证明存在历史版本存储。
3. **样式切换：** 选择风格 → 复制目标样式配置并保留部分当前选项 → 更新 `cssConfig` → 保存样式。正文与配置独立处理，提示我们自己的模板切换也应避免改写正文。

### 能看出什么技术，不能看出什么

页面 DOM 有 Ant Design 类名，脚本有 React 渲染调用、Umi 路由和构建产物，支持“React / Umi / Ant Design 相关前端实现”的判断。包里个别依赖的许可证版本不能据此当成整站 React 版本。`/api/resume/*` 路径也不能证明后端使用 Java、Spring、Node 或某种数据库。服务端框架、存储结构和 PDF 服务引擎均未证实。

## 4. 对产品范围的启示

观察到的核心路径是模块化编辑、模板预览及文件操作；使用者能够区分用途副本、正在保存的内容与导出文件，才能避免误操作。哪些功能纳入本项目由[业务需求](../requirement/04-个人CV制作与管理需求说明.md)确定，具体取舍见[产品设计](../design/02-CV制作管理与展示设计.md)。
