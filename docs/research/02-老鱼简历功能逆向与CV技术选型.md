# 老鱼简历 UIUX 与字段调研

观察日期：2026-11-03（Asia/Shanghai）。对象为[老鱼简历](https://www.laoyujianli.com/)中的个人简历管理、常规编辑器和相关面板。本文保留实测、公开代码线索与设计判断；产品范围仍由[业务需求](../requirement/04-个人CV制作与管理需求说明.md)决定。CVory 的新页面组织属于评审建议，见[产品设计](../design/02-CV制作管理与展示设计.md)及根 [DESIGN](../../DESIGN.md)。

## 1. 方法与验证边界

- **页面实测**：Chrome CUA 复用负责人打开的会话，进入简历库、现有简历编辑器，展开教育与工作表单，点击纸张中的技能模块，查看布局、间距、模板、导出与分享面板。只观察字段名称、控件与交互，不将个人内容或私有对象地址写入文档、Figma 或附件。
- **公开代码**：从实际页面 DOM 的 `script[src]` 定位主包，以普通 GET 读取公开资源。REA 将 JavaScript 当作惰性文本解析，不执行下载代码，不调用简历业务 API。
- **未验证**：没有新建、改写、复制、删除、上传、下载、发布或切换模板；没有改动分享开关和脱敏设置。保存提示不算可靠保存测试，格式入口不算文件验证。没有验证竞品手机布局、键盘流程、异常恢复、服务器权限或完整数据模型。
- 当前 Chrome 没有暴露可供 REA 直接连接的 loopback CDP 端点；本机端点文件不等于服务可用，目标探测返回无效响应后没有改动浏览器启动配置。浏览器观察由 CUA 完成；REA 用于公开配置模块的静态解析。完整主包分析遇到堆内存上限，没有得到全站语义图谱。

## 2. 页面与任务组织

| 场景 | 页面实测 | 交互含义 |
| --- | --- | --- |
| 首页 | 模板搜索、分类、模板封面与“我的简历”入口 | 首页面向获客和模板发现，不能直接当作个人管理工作区 |
| 我的简历 | 左侧“我的简历／收藏模板／公开简历”，右侧“从模板新建／Markdown 简历／导入简历／AI 智能生成”等标签 | 继续编辑与创建同时可达；多组标签、推荐与商业入口增加视觉负担 |
| 简历条目 | 封面、名称、更新时间，分享／复制／下载／改名／删除图标 | 文档识别依赖封面和名称；图标动作需要可发现的名称，危险动作应与编辑分开 |
| 编辑器 | 顶部返回、文档名、保存时间、翻译／分享／导出；左侧模块，中间结构化表单，右侧排版工具与纸张 | 区分文档操作、内容操作和外观操作；预览常驻使修改与结果紧邻 |
| 模块与条目 | 左侧包含开关，基本信息开关不可关闭；表单模块头有上下移、改名、删除和收起图标，经历内有添加／删除条目入口 | 当前模块、模块显示、模块顺序和条目顺序是不同状态；图标存在不代表已实测排序和删除语义 |
| 预览联动 | 点击纸张中的专业技能模块后，表单出现 `skillName` 与一个富文本编辑器 | 预览可以作为定位入口，不只是只读缩略图；该联动已实际点击验证 |
| 分页 | 页面显示页数，分页处有内容切割提示，并有“智能一页”入口 | 分页是编辑反馈的一部分；一页压缩效果未验证 |

编辑器以三栏在同屏组织，滚动同步的可靠性没有验证。当前观察中仅展开一个主要模块；切换到教育、工作后出现对应结构化字段与正文工具栏。不能据此保证所有模板、模块或长内容都采用同一滚动策略。

## 3. 字段与控件

### 3.1 核心字段清单

“页面＋配置”表示两类证据都存在；“配置”只表示公开前端定义存在，不代表已在当前简历中启用或完成服务端验证。

| 模块 | 字段 | 控件与证据 |
| --- | --- | --- |
| 基本信息 | 姓名、电话、邮箱、头像 | 文本／邮箱、上传入口；页面＋配置 |
| 求职意向 | 当前状态、职位名称、期望工作地 | 可输入选择、文本；页面＋配置 |
| 扩展个人信息 | 学历、个人网站、微信、GitHub、城市、期望薪资、工作年限、年龄 | 当前简历中可见部分字段和“更多”入口；配置提供完整名单，字段是否默认显示受配置影响 |
| 教育经历 | 学校、专业、学历、在读时间、学历类型、学院、所在城市、在校经历 | 文本、可输入选择、起止日期与富文本；页面＋配置 |
| 工作经历 | 公司名称、在岗时间、部门名称、岗位名称、工作城市、工作详情 | 文本、起止日期（结束可为至今）、富文本；页面＋配置 |
| 专业技能 | 技能名称、技能描述 | 输入与富文本；页面定位后检查控件，配置核对语义 |
| 项目经历 | 项目名称、项目角色、项目城市、项目链接、始末时间、项目详情 | 文本、起止日期、富文本；配置，未启用当前简历的隐藏项目模块 |
| 作品集 | 作品名称、作品链接、作品图片、作品详情 | 文本、图片上传、富文本；配置 |
| 荣誉奖项 | 奖项名称、获奖时间 | 富文本与单日期；配置 |
| 其他／研究经历 | 名称、角色、部门、城市、时间与详情 | 文本、起止日期、富文本；配置 |
| 个人简介／自定义 | 简介正文；自定义名称、时间、内容等 | 配置提供富文本字段；不从标签推断必填性与完整服务端约束 |

配置还包含性别、身高、体重、籍贯、民族、政治面貌、婚姻状况等字段。它们是竞品事实，不自动进入 CVory；默认表单优先呈现与职业经历和联系有关的信息，新增字段范围仍需按产品需求评审。

### 3.2 不宜直接照搬的细节

- 配置键 `old` 的 `displayName` 为“年限”，当前页面显示“年龄”，占位提示是年龄单位；字段键、配置文案与最终 UI 并非一一相同。
- `jobDetail` 配置称“工作描述”，当前表单称“工作详情”；`customCity` 的配置显示名为“学历”。这些都需要语义校对，不能机械复制字段表。
- 文本控件的存在不证明邮箱、链接、日期顺序或必填校验完备。日期可以“至今”，新设计应明确结束状态，不依赖任意文字输入猜测。
- 头像上传入口不能证明裁剪比例、格式限额或资源授权；导入声明也不能当作解析保真承诺。

### 3.3 证件照与账户头像

实际 DOM 中，简历照片在填写区和纸张中分别渲染为图片，观测框约为 72 × 88 px 与 58 × 68 px，采用 `object-fit: cover`；上传入口为单文件，旁边有位置调整入口。账户头像与简历内容照片是不同用途。此次点击上传与照片后没有得到可核对的网页裁切面板，未选择或提交文件，因此不能把竞品的裁切比例、格式限额或失败恢复写成实测结论。

CVory 采用独立 3:4 证件照、同源裁切和隐藏／移除区分，是设计建议；比例不机械照搬上述 DOM 尺寸。纸张边界、图标与表单依然由原生设计图层组成，照片只作为内容资源。

### 3.4 富文本

教育与工作表单实际显示撤销／重做、字号、行高、加粗、斜体、下划线、列表、链接、颜色、对齐、缩进、全屏与清除样式，并有 AI 优化和简历助手入口。这里验证的是工具入口与编辑区存在，没有改写内容或触发 AI。

CVory 的首版建议保留当前需求支持的加粗、斜体、列表、链接与行内代码等基础格式，将字体与版面参数归入统一样式设置；不要让每段正文各自维护一套不受约束的字体和行高。

## 5. 从零设计的取舍建议

以下是设计判断，不是已确认业务要求：

1. **简历库先服务继续编辑。** 文档封面、名称、更新时间、编辑入口形成一个清楚的卡片；创建入口集中到标题区，样式在创建 Dialog 内选择，避免简历管理与模板浏览互相争夺注意力。
2. **内容与样式分开。** 模块导航负责定位；表单负责结构化信息和正文；纸张负责结果反馈；字体、行距和页边距按需进入样式 Sheet。
3. **减少同时暴露的字段。** 个人信息、联系方式、求职信息分组；扩展字段按需添加。重复经历复用同一组字段、日期规则与富文本工具栏。
4. **状态长期可见。** 未保存、保存中、已保存、失败和冲突应可区分；失败保留输入。“隐藏模块”不清空数据；删除明确对象。
5. **桌面与窄屏各自组织。** 桌面内容和预览并列；手机切换编辑／预览并保留上下文。移动端是我们的设计建议，未将竞品手机体验当作已验证依据。
6. **保持已确认的视觉意图。** 黑白灰、Geist、无边框、少量蓝色；不把竞品的蓝紫面板、会员推荐和营销入口一起引入。

首版草稿不扩展 AI、招聘、会员、范文或模板市场。未画出的能力不记为设计交付，未实现的入口不记为运行完成。
