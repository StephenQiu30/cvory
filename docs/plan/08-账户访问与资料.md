# 账户访问与资料

唯一来源 PRD：[PRD 08](../prd/08-账户访问与资料.md)。PLAN-CV-08。设计和验收的已确认／建议状态以来源为准，不自动授权公开部署。

## 1. 交付目标

让多人安全访问各自的私有工作区，维护账户资料，并以可验证的隔离与迁移支持运行。

## 2. 执行步骤

1. 对照当前 FastAPI 账户、会话、限流及前端弹窗与 PRD 的 AC，记录现有能力和缺口；确认公网目标、代理信任、认证策略与负载门槛。
2. 在隔离 MySQL 盘点 schema、归属、邮箱唯一性及 legacy，准备备份、版本化迁移及失败恢复；先兼容后回填，收紧约束前验证数据，不自动认领 legacy。
3. 以服务端会话为唯一 owner 来源，逐一核对账户、CV、照片、预设、候选、PDF、发布与缓存；实现缺失的跨账户隔离和不同账户重新登录时的草稿保护。
4. 根据已确认策略完善密码哈希演进、来源/CSRF、可信代理、Cookie、会话有效期与撤销、分维限流和脱敏日志；同步 OpenAPI、生成客户端与调用方。
5. 按设计完善资料和手机／桌面弹窗的键盘、状态与错误反馈；保存失败和认证失效不清除用户输入。
6. 在隔离环境执行 PRD 的账户、隔离、限流并发、会话和迁移场景；执行 `cd backend && uv run pytest -v`、`cd frontend && pnpm lint && pnpm build` 及隔离前后端下的 `pnpm exec playwright test`。真实 MySQL 和目标 HTTPS 环境单独验证。

7. 将历史、本机恢复、打印票据及执行器绑定纳入两账户隔离矩阵，保留重新认证前的输入。

## 3. 完成条件

AC-USER-01～08、18；区分局部验证、完整能力验收和公网开放验收。结果与环境留 HANDOVER；确认、优先级和阻塞见 BACKLOG。
