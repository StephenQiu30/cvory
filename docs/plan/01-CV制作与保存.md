# CV制作与保存

唯一来源 PRD：[PRD 01](../prd/01-CV制作与保存.md)。PLAN-CV-01。

## 1. 交付目标

形成可新建、编辑、保存并重开的 CV，是其他能力使用的内容基础。

## 2. 执行步骤

1. 按 PROJECT 的目录与规范，维护 frontend/ Next.js 与 backend/ NestJS + TypeScript，在隔离环境验证单一后端链路，保留既有数据，锁定精确依赖、Node.js/TypeScript 版本与 pnpm；明确所有者登录及运行配置，接入 MySQL、迁移与私有头像目录。把真实运行与检查命令登记 PROJECT 和 README。
2. 对照现存 OpenAPI/MySQL/文件/会话及注销墓碑格式建立兼容测试，再实现 NestJS DTO、Guard、业务模块和数据库事务，先在隔离环境对照后切换；旧后端移除按设计迁移验收处理。
3. 在管理页面及 CV 模块实现新建、基本资料、重复经历、排序/隐藏与头像；使用稳定对象标识，不把示例写成真实内容。
4. 接入受限 Tiptap 和 Markdown 输入，正文 JSON 统一保存与只读渲染；中文组合输入、格式取消和键盘操作可用。
5. 在 NestJS 实现校验、事务和条件更新，按 PROJECT 的 API 约定生成 OpenAPI 与前端类型。前端接入保存反馈、失败保留与重试、etag 冲突提示，新修改不能被旧响应确认或覆盖。
6. 真实保存后关闭并重开服务，核对 MySQL 与头像持久化读回；验证断网、双标签、不支持粘贴、未登录写入、校验错误形状和旧 etag 拒绝。
7. 将管理工作区组织为独立路由组，建立共享 BasicLayout、Header、Footer；按参考页建立左侧简历条目、右侧模板／Markdown／导入标签的双栏工作台和窄屏纵排；复用真实公开管理、改名、复制、导出和导入流程，使用 shadcn 风格组件及 Radix Dialog/Tabs，编辑路由继续使用沉浸式布局。

8. 按来源 PRD 实现自动保存的串行提交、修订号和保存并离开的最新输入屏障；在真实 API 延迟期间继续输入再返回，重开核对最后内容。
9. 接入按 owner／CV／格式版本隔离的浏览器恢复候选；演练刷新、关闭、会话过期、账号切换、退出及存储失败；对非法根／marks／属性等验证实际 HTTP 错误与未修改的 MySQL 数据。

补充步骤：实现可持续的 Markdown 源码编辑/预览与富文本切换；共用规范正文，测试受支持语义往返、不兼容格式警告和取消，结构化字段不变。验证 AC-MD-01、02，不能仅交付粘贴导入。

## 3. 验证与完成条件

新增 AC-MD-01、02 与既有制作/保存验收一并通过。

AC-CV-01、02、05～16、42～46；TC-CV-01、03～06、22～25。保留持久化读回和真实浏览器证据，不以组件快照代替保存成功。
