# BOSS 直聘自主投递

唯一来源 PRD：[PRD 11](../prd/11-BOSS直聘自主投递.md)。PLAN-CV-11。依赖和实施状态在 BACKLOG。

## 1. 交付目标

在 CVory 内准备固定材料、选择岗位、启动用户控制的执行，并准确核对每项沟通/招呼结果及独立人工 PDF 准备状态，支持停止和故障恢复。

## 2. 执行步骤

1. 按来源需求的范围审查候选开源模块，固定 commit、许可证、依赖、NOTICE 及第三方资源边界；按已选 Chrome 插件方向核对扩展模块适配成本。只读核对官方登录、岗位定位、沟通/招呼动作及当前平台限制，把复用范围和 Chrome 分发方式回写设计，不整体合并上游产品。
2. 在隔离 MySQL 定义 owner 归属的岗位候选、任务、不可变材料及动作记录；落实条件写入、幂等键、领取租约和注销清理。OpenAPI 由 NestJS 产生，生成前端调用；不把平台会话存到 CVory。
3. 复用保存与 PDF 流程固定输入，选择 PDF 时关联文件摘要并引导用户在 BOSS 官方页面手工上传，形成材料/招呼预览及确认页；未授权只允许准备。实现岗位逐项选择、任务列表和准确汇总，不引入未定义配额或成功率。
4. 实现自有执行器的一次性配对、身份绑定、心跳与撤销；任务按权限领取。增加独立模拟适配器验证所有状态，不以模拟器作为真实发送后备。账号不符、租约丢失或连接失效时停止新动作。
5. 适配建立沟通和招呼两个动作，人工 PDF 仅记录用户确认；不实现自动上传/附件发送，逐步采集最少可核实证据；实现 needs_user、unknown、平台限制和对方许可分支。回执丢失先核查，不自动重发；暂停与取消只阻止后续动作，界面保留在途结果。
6. 在隔离浏览器和模拟平台覆盖 PRD 全部故障矩阵，检查两账户、双执行器、重启、延迟、重复确认和注销。按变更执行后端、前端及浏览器适用检查；目标运行环境验证设备连接和文件边界。
7. 仅在用户明确指定账号、岗位、动作及范围后验证真实平台闭环。核对平台沟通和招呼事实；人工 PDF 只记录来源明确的用户确认，去除敏感证据后记录结果；没有授权或遇验证码则保留未验收状态，不发送、不绕过、不补造通过记录。

补充步骤：按 MV3 浏览器插件目标固定配对/侧栏/content script/service worker 边界；实现关键词、排除词、城市/薪资三态筛选及可选 AI 解释。冻结资产而非发送时读取可变存储；以持久历史覆盖跨任务去重，验证 worker 回收后未知结果不重发。验证首期没有自动 PDF/PNG 发送，用户确认上传不会生成平台送达状态。覆盖 AC-BOSS-13～15。

## 3. 完成条件

AC-BOSS-01～15 与 TC-BOSS-01～07 分别留证；必须区分准备、模拟、只读核查和真实平台结果。一个动作失败或未知不能报告整项简历已送达。自动附件不在首期完成条件内；不能用人工确认冒充真实附件验收。
