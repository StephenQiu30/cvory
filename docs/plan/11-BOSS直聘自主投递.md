# BOSS 直聘自主投递

唯一来源 PRD：[PRD 11](../prd/11-BOSS直聘自主投递.md)。PLAN-CV-11。依赖和实施状态在 BACKLOG。

## 1. 交付目标

在 CVory 内准备固定材料、选择岗位、启动用户控制的执行，并准确核对每项沟通/招呼结果及独立人工 PDF 准备状态，支持停止和故障恢复。

## 2. 执行步骤

1. 固定 GitHub 复核提交、许可证、NOTICE 及第三方资源边界。jitou 只作模式参考；boss-helper 的 MIT 与 README 商用限制未澄清，不复制其代码。核对官方协议：可查旧版包含第三方工具限制，当前现行版本未能核实；负责人确认没有或不确定拥有书面授权。此授权门槛落实为当前实现不申请 BOSS 域名权限、不注入脚本、不读取页面/Cookie/API、不发送消息。协议复核、结论及 Chrome MV3 运行限制见[调研 03](../research/03-BOSS直聘自动投递简历方案与自研可行性调研.md)。
2. 先在隔离 MySQL 定义 owner 归属的手工岗位、偏好及离线任务；创建任务时固定 CV 内容/etag、岗位、规则依据和招呼草稿，requestId 幂等，允许查询、离线模拟和删除。OpenAPI 由 NestJS 产生，前端调用；不保存平台凭据。真实设备配对、平台账号绑定和任务领取留待授权门槛满足后。
3. 复用保存与 PDF 流程固定 CV 版本，提供 PDF 供用户自行在官方页面处理；CVory 记录仅限用户报告的人工准备状态。实现手工岗位录入、逐项选择、关键词/排除词/城市/薪资硬筛选与招呼草稿。AI 匹配只允许用户明确预览输入和主动付费调用。离线流程不能显示为已投递。
4. 实现独立 offline task status transition，覆盖幂等创建、快照读取、模拟和删除；不包含 BOSS page adapter、host permission、content script、Cookie 或接口调用，也不作为真实发送后备。每项结果都显示模拟来源；不得产生真实成功、已读、回复或附件状态。
5. 实现任务暂停、取消、去重和恢复记录的数据合同，但离线任务不得以模拟器虚构发送结果。MV3 future worker 状态按 Chrome 生命周期持久恢复；重启前后的中断项保持待核实/unknown，不自动重放。
6. 按 AC-BOSS-01、03～06、10、12～14、16～17 及 TC-BOSS-08 验收手工数据隔离、硬条件三态、固定任务快照、requestId 幂等、模拟文案、删除和无 BOSS 网络/页面访问。真实 MySQL、浏览器及构建证据按 HANDOVER 记录。
7. AC-BOSS-02、07～11、15 和 TC-BOSS-01～07 中的平台真实闭环仍属完整目标，当前不执行真实平台访问。只有重新核对现行官方条款并取得适用书面授权、重新评审和明确操作范围后，才能设计/实现真实 adapter；没有授权或遇验证码则保持阻止，不绕过、不发测试消息、不补造通过记录。

补充步骤：离线阶段实现关键词、排除词、城市/薪资三态筛选及可选 AI 解释；只接受手工/合成岗位。后续取得授权后再实现 MV3 配对/侧栏/content script/service worker、最小域名权限、固定资产、跨任务去重及 worker 回收恢复。首期不生成任何 PDF/PNG 自动附件动作，用户报告上传不生成平台送达状态。

## 3. 完成条件

离线阶段 AC-BOSS-01、03～06、10、12～14、16～17 与 TC-BOSS-08 分别留证；必须区分准备和模拟，不产生真实平台结果。AC-BOSS-02、07～11、15 及 TC-BOSS-01～07 的真实平台/设备部分保持未验收，直至授权门槛满足。一个动作失败或未知不能报告整项简历已送达。自动附件不在首期完成条件内；不能用人工确认冒充真实附件验收。
