# BOSS 直聘自主投递

唯一来源 PRD：[PRD 11](../prd/11-BOSS直聘自主投递.md)。PLAN-CV-11。依赖和实施状态在 BACKLOG。

## 1. 交付目标

在 CVory 内准备固定材料、选择岗位、启动用户控制的执行，并准确核对每项沟通、文字及附件结果，支持停止和故障恢复。

## 2. 执行步骤

1. 按来源需求的范围审查候选开源模块，固定 commit、许可证、依赖、NOTICE 及第三方资源边界；比较 Python 本地执行器与扩展的适配成本。只读核对官方登录、岗位定位、沟通／附件动作及当前平台限制，把择一后的接入方式回写设计，不整体合并上游产品。
2. 在隔离 MySQL 定义 owner 归属的岗位候选、任务、不可变材料及动作记录；落实条件写入、幂等键、领取租约和注销清理。OpenAPI 由 FastAPI 产生，生成前端调用；不把平台会话存到 CVory。
3. 复用保存与 PDF 流程固定输入，关联实际文件内容摘要，形成材料预览及用户确认页；未授权只允许准备。实现岗位逐项选择、任务列表和准确汇总，不引入未定义配额或成功率。
4. 实现自有执行器的一次性配对、身份绑定、心跳与撤销；任务按权限领取。增加独立模拟适配器验证所有状态，不以模拟器作为真实发送后备。账号不符、租约丢失或连接失效时停止新动作。
5. 适配沟通、招呼和附件三个独立动作，逐步采集最少可核实证据；实现 needs_user、unknown、平台限制和对方许可分支。回执丢失先核查，不自动重发；暂停与取消只阻止后续动作，界面保留在途结果。
6. 在隔离浏览器和模拟平台覆盖 PRD 全部故障矩阵，检查两账户、双执行器、重启、延迟、重复确认和注销。按变更执行后端、前端及浏览器适用检查；目标运行环境验证设备连接和文件边界。
7. 仅在用户明确指定账号、岗位、动作及范围后验证真实平台闭环。核对平台会话、招呼和附件实际事实，去除敏感证据后记录结果；没有授权或遇验证码则保留未验收状态，不发送、不绕过、不补造通过记录。

## 3. 完成条件

AC-BOSS-01～12 与 TC-BOSS-01～07 分别留证；必须区分准备、模拟、只读核查和真实平台结果。一个动作失败或未知不能报告整项简历已送达。未执行真实附件验证时，该项不能记为产品验收通过。
