# 邮箱验证与账户恢复

唯一来源 PRD：[PRD 09](../prd/09-邮箱验证与账户恢复.md)。PLAN-CV-09，仅服务仍启用邮箱凭据的存量兼容；GitHub-only 不执行本计划，实施与验证状态见 BACKLOG。

## 1. 交付目标

使存量邮箱用户能验证邮箱并安全恢复或更新凭据；实际投递必须可验证。

## 2. 执行步骤

1. 按设计中验证前私有访问与发布门槛、24 小时验证／30 分钟重置及 8–128 位密码规则实施；运行前选定发信渠道、域名及配额，回写设计的运营参数，不将未选供应商当作整个功能的审批阻塞。
2. 在唯一 `backend/schema.sql` 中定义账户验证状态与一次性令牌表；实现原子消费事务，覆盖旧账户、重复操作、邮箱快照、跨账户确认、邮件扫描、过期与并发；令牌只存哈希，发送密文短期保留。
3. 建立经确认的邮件发送边界、重试与清理，确保发送失败不伪装成功，不在日志泄露凭据；控制邮箱枚举与限流。
4. 实现验证、重置、凭据修改和会话撤销的 API、OpenAPI 客户端和当前页面流程；旧账户仍可登录并保留历史公开快照，发布验证门槛在服务端执行，错误和超时保留安全上下文。
5. 在隔离数据库和受控收件箱分别验证各状态、并发与重放、旧会话撤销、枚举防护以及实际投递；运行项目适用的后端、前端与浏览器检查。

6. 连续验证注册／登录、验证邮件实际收到、链接确认、发布门槛、忘记密码和旧会话失效；发信器接收、真实收件和业务消费分别记录，不能相互替代。

## 3. 完成条件

AC-USER-09～13 和 PRD 对应场景通过；只有模拟邮件时不得声称真实投递验证。依赖与阻塞见 BACKLOG。
